# Docker 命令词典

> 用法：先按**组**找命令，再看 `docker run` 选项大表，最后看「输出怎么读」。
> 所有命令都可用 `docker <cmd> --help` 查全量选项。

---

## 一、镜像相关

| 场景 | 命令 | 说明 |
|---|---|---|
| 构建镜像 | `docker build -t 名:tag .` | 结尾 `.` 是**构建上下文**，不是可有可无的 |
| 列出本地镜像 | `docker images` / `docker image ls` | 只看本地，不查仓库 |
| 拉取 | `docker pull nginx:1.27-alpine` | 逐层下载，已有的层跳过 |
| 推送 | `docker push 用户/名:tag` | 要先 `docker login` |
| 打标签 | `docker tag 旧 新:tag` | 只是加一个引用名，不复制数据 |
| 看分层 | `docker history 名:tag` | 每条构建指令 → 一行；`--no-trunc` 看完整命令 |
| 看元数据 | `docker inspect 名:tag` | JSON：Config.Cmd/Entrypoint/Env、Architecture |
| 删镜像 | `docker rmi 名:tag` | 被容器占用时需先删容器，或 `-f` |
| 导出/导入 | `docker save -o a.tar 名` / `docker load -i a.tar` | 离线搬镜像用 |
| 清理悬空镜像 | `docker image prune` | 加 `-a` 删所有未使用镜像 |

⚠️ `docker commit`（把容器改动固化成镜像）能用但不推荐：不可复现，正式做法写 Dockerfile。

## 二、容器生命周期

| 场景 | 命令 | 说明 |
|---|---|---|
| 创建+启动 | `docker run ...` | = `create` + `start` |
| 只创建 | `docker create ...` | 便于先配好再起 |
| 启动/停止 | `docker start 名` / `docker stop 名` | stop 发 SIGTERM，超时(默认10s)再 SIGKILL |
| 重启 | `docker restart 名` | ⚠️ 不会恢复可写层里被删的数据，也不会重读镜像改动 |
| 强杀 | `docker kill 名` | 发 SIGKILL；可 `-s SIGTERM` 指定信号 |
| 暂停/恢复 | `docker pause` / `unpause` | 冻结进程（cgroup freezer），不是停止 |
| 删除 | `docker rm 名` | 加 `-f` 强删运行中的；`-v` 同时删匿名卷 |
| 改名 | `docker rename 旧 新` | |

## 三、查看与排障

| 场景 | 命令 | 说明 |
|---|---|---|
| 看运行中容器 | `docker ps` | 加 `-a` 看全部（含已退出）；`-q` 只出 ID |
| 看日志 | `docker logs 名` | `-f` 跟随，`--tail 100`，`--since 10m` |
| 详细状态 | `docker inspect 名` | **排障第一站**：`State.ExitCode` / `OOMKilled` / `FinishedAt` |
| 进容器 | `docker exec -it 名 sh` | 不重启主进程；`sh` 不存在就换 `bash` 或看 `05` |
| 单次执行 | `docker exec 名 cat /etc/os-release` | 非交互场景 |
| 进程表 | `docker top 名` | 宿主视角的进程 |
| 资源占用 | `docker stats` | CPU/内存/网络/IO 实时（`--no-stream` 取一次） |
| 拷文件 | `docker cp 名:/路径 ./本地` | 双向都可 |
| 看改动 | `docker diff 名` | A/C/D 列出相对镜像的增/改/删 |
| 端口映射 | `docker port 名` | 看 `-p` 实际生效的映射 |
| 事件流 | `docker events` | 全局，观察起停/健康检查 |
| 容器内设等 | `docker update --memory 256m 名` | 运行中改限额 |

## 四、网络

| 场景 | 命令 | 说明 |
|---|---|---|
| 列表 | `docker network ls` | 默认有 bridge / host / none |
| 创建自定义网络 | `docker network create mynet` | **同一自定义网络内可用容器名互访**（内嵌 DNS） |
| 查详情 | `docker network inspect mynet` | 看有哪些容器、各自 IP |
| 把容器接进网络 | `docker network connect mynet 名` | 运行中也能接 |
| 断开 | `docker network disconnect mynet 名` | |
| 删除 | `docker network rm mynet` / `prune` | |

| 网络模式 | 含义 | 何时用 |
|---|---|---|
| `bridge`（默认） | 私有网桥 + NAT，需 `-p` 暴露 | 单机常规 |
| `host` | **共用宿主网络栈**，无隔离，`-p` 无意义 | 极致性能/临时 |
| `none` | 无网络 | 完全离线任务 |
| `container:名字` | 复用另一个容器的网络栈 | sidecar 场景（K8s Pod 类似） |

✍️ 默认 `bridge` **不支持按容器名解析**，自定义网络才支持 —— Day 4 会实测。

## 五、存储

| 场景 | 命令 | 说明 |
|---|---|---|
| 建卷 | `docker volume create webvol` | 由 Docker 管理，存在 `/var/lib/docker/volumes` |
| 列表/详情 | `docker volume ls` / `inspect webvol` | 看 Mountpoint |
| 删除 | `docker volume rm webvol` / `prune` | |

| 挂载方式 | 写法 | 特点 |
|---|---|---|
| **命名卷** | `-v webvol:/data` | Docker 管理生命周期，**删容器不删卷**（除非 `rm -v`） |
| **绑定挂载** | `-v /宿主/路径:/data` | 直接挂宿主目录，改文件立刻生效（开发常用） |
| **tmpfs** | `--tmpfs /tmp` | 只存内存，容器停即失 |
| **现代写法** | `--mount type=volume,src=webvol,dst=/data` | 语义更清楚（区分 volume / bind） |

⚠️ 三个坑：路径写错会**静默新建目录**；挂到非空目录会**遮住**原有内容（K8s 里叫覆盖，Linux 侧同理）；`--rm` 不删命名卷。

## 六、系统与清理

| 场景 | 命令 | 说明 |
|---|---|---|
| 看磁盘占用 | `docker system df` | 镜像/容器/卷/缓存各占多少；`-v` 更细 |
| 总清理 | `docker system prune` | 清停止的容器+悬空镜像+未用网络；`-a` 更狠；`--volumes` 连卷一起删 ⚠️ |
| 分类清理 | `docker container prune` / `image prune` / `volume prune` | 更可控 |
| 构建缓存 | `docker builder prune` | 缓存也能占好几 GB |
| 环境信息 | `docker info` | Storage Driver、Cgroup 版本、根目录 |

## 七、`docker run` 选项大表（最高频）

> **先记住分界规则（三段式）**：`docker run [DOCKER 的选项...] 镜像名 [镜像里要跑的命令 + 它的参数...]`
> 第一个"非选项"参数就是**镜像名**，它后面的东西 docker **原样当成"容器内的命令"**，一个都不解析。
> 例：`docker run --rm alpine:3.22 ping -c1 8.8.8.8` → `--rm` 是 docker 的，`ping -c1 8.8.8.8` 是**容器里的**（`-c1` 是 `ping` 自己的参数：只发 1 个包）。
> 不写"镜像里的命令"时，就用镜像的 `CMD`。

| 选项 | 作用 | 备注 |
|---|---|---|
| `-d` | 后台运行 | 不加则占住终端 |
| `-it` | 交互 + 分配 TTY | 常配 `sh`/`bash` 调试 |
| `--rm` | 退出即删容器 | 临时实验必备 |
| `--name web` | 起名字 | 不写则随机名 |
| `-p 8080:80` | 宿主端口:容器端口 | 只写 `-p 80` 会随机映射宿主端口 |
| `-P` | 按 EXPOSE 随机映射 | |
| `-e KEY=VALUE` | 环境变量 | 可重复；`--env-file` 从文件读 |
| `-v 源:目标` | 挂载 | 见第五节 |
| `--network mynet` | 指定网络 | |
| `--restart always` | 崩溃/重启宿主后自动拉起 | 可选 `on-failure[:N]`、`unless-stopped` |
| `--entrypoint /bin/sh` | **覆盖**镜像的 ENTRYPOINT | 排查镜像启动问题常用 |
| `-u 1000:1000` | 指定用户 | 安全实践（Day 6） |
| `-w /app` | 工作目录 | |
| `--cpus 0.5`、`-m 256m` | CPU/内存限额 | 超内存 → OOMKilled(137) |
| `--cap-drop=ALL` | 把**能力位全清零**（Eff/Prm/Bnd 全归 0） | 安全加固主力；⚠️ 能力名**不带 `CAP_` 前缀** |
| `--cap-add=NET_RAW` | 在 drop 之后再**加回某一个**能力 | 顺序有意义：`--cap-drop=ALL` 在前、`--cap-add` 在后 |
| `--sysctl k=v` | 写一个**命名空间化**的内核参数 | 只放行 `net.*` 这类；全局参数（`vm.*`）会被拒。⚠️ **不写 ≠ 用内核默认值** —— Docker 会注入自己的默认（实测：`ping_group_range` = `0 2147483647`（内核默认空区间）、`ip_unprivileged_port_start` = `0`（内核默认 `1024`）） |
| `--security-opt no-new-privileges` | 禁止 `execve` 时提权（setuid / file caps 全失效） | 一句话堵死提权 |
| `--privileged` | 几乎不隔离 ⚠️ | 给全部能力 + 放行所有设备 = 交出宿主控制权 |
| `--read-only` | 根文件系统**挂载为只读** | 配合 `--tmpfs` 给可写处 |
| `--tmpfs /tmp` | 挂一个**内存文件系统** | 常与 `--read-only` 搭配 |
| `-h myhost` | 容器主机名 | |
| `--add-host a:1.2.3.4` | 加 hosts 记录 | |
| `--health-cmd` | 自定义健康检查 | |

## 八、输出怎么读（逐字段）

**`docker ps`**

| 列 | 含义 |
|---|---|
| CONTAINER ID | 容器短 ID（`inspect`/`exec` 都能用短 ID） |
| IMAGE | 用哪个镜像起的 |
| COMMAND | 容器内 **PID 1** 的启动命令 |
| STATUS | `Up 3 minutes` / `Exited (137) 2 minutes ago` ← **排障先看这列** |
| PORTS | 端口映射；`0.0.0.0:8080->80/tcp` |
| NAMES | 名字（`--name` 起的或随机的） |

**`docker images`**：REPOSITORY / TAG / IMAGE ID / CREATED / SIZE（SIZE 是**共享层去重后**的本镜像体积）

**`docker history`**：IMAGE（层ID）/ CREATED / CREATED BY（**对应哪条指令**）/ SIZE ← 验证"每条指令一层"靠它

**`docker inspect` 关键字段**

| 路径 | 用途 |
|---|---|
| `State.Status` / `ExitCode` / `OOMKilled` | 活着吗 / 怎么退的 / 是不是被内存杀 |
| `State.StartedAt` / `FinishedAt` | 时间线 |
| `Config.Cmd` / `Entrypoint` | 镜像定义 vs 实际执行 |
| `Config.Env` | 环境变量（⚠️ `ENV`/`ARG` 的值都躺在这里，**明文的**） |
| `Config.User` | 镜像里 `USER` 设的身份；空 = root |
| `NetworkSettings.Ports` | 端口映射是否生效 |
| `Mounts` | 卷挂到哪了 |
| `HostConfig.RestartPolicy` | 重启策略 |

## 九、常用组合（可复制）

| 目的 | 一条命令 |
|---|---|
| 跑完即走 | `docker run --rm -it alpine sh` |
| 起服务 | `docker run -d --name web -p 8080:8080 webapp:v1` |
| 看最近日志 | `docker logs --tail 50 -f web` |
| 进运行中容器 | `docker exec -it web sh` |
| 查退出原因 | `docker inspect web --format '{{.State.ExitCode}} {{.State.OOMKilled}}'` |
| 一键清干净 | `docker system prune -af --volumes` ⚠️ 会删数据卷 |
| 两个容器互 ping | `docker network create n && docker run -d --name a --network n alpine sleep 300` |
| 看容器有哪些能力 | `docker run --rm alpine:3.22 grep ^Cap /proc/self/status` |
| 最小能力跑服务 | `docker run --rm --cap-drop=ALL -p 8080:8080 webapp:v4` |
| 只读根 + 可写 /tmp | `docker run --rm --read-only --tmpfs /tmp -p 8080:8080 webapp:v4` |
| 非 root 跑 | `docker run --rm -u 10001:10001 webapp:v4` |

## 十、易错点：选项的"归属"与表达方式（Day 6）

### 10.1 三段式：谁在解析哪个参数

| 实例 | docker 的选项 | 镜像 | 镜像里的命令 |
|---|---|---|---|
| `docker run --rm --cap-drop=ALL alpine:3.22 ping -c1 8.8.8.8` | `--rm` `--cap-drop=ALL` | `alpine:3.22` | `ping -c1 8.8.8.8` |
| `docker run -d --name web -p 8080:8080 webapp:v4` | `-d` `--name web` `-p 8080:8080` | `webapp:v4` | （无 → 用镜像的 `CMD`） |
| `docker run --rm alpine:3.22 sh -c 'grep ^Cap /proc/self/status'` | `--rm` | `alpine:3.22` | `sh -c '...'` |

⚠️ 常见误读：把 `-c1`、`-p 80`、`-it` 全当成 docker 的选项 —— 只要**落在镜像名之后**，就都是容器内命令的参数。

### 10.2 高频坑

| 坑 | 说明 |
|---|---|
| 能力名带 `CAP_` 前缀 | 内核/手册里叫 `CAP_NET_RAW`，**docker 和 K8s 里要写 `NET_RAW`**（去掉前缀）；写 `--cap-add=CAP_NET_RAW` 直接报错。K8s：`securityContext.capabilities.add/drop` 同样不带前缀（见 `docs/k8s_in_action/06-机制与安全.md` §4） |
| 想用 `RUN` 改 `/proc/sys/...` | `/proc/sys` 是**内存伪文件**，写在镜像里不生效；要运行时的 `--sysctl`（且只能改命名空间化的参数） |
| `--cap-drop=ALL` 写在 `--cap-add` 后面 | 顺序有语义：drop 在前、add 在后，净结果才是"只留 add 的那个" |
| 以为"绑低端口要 root" | 判定式：**端口 < `ip_unprivileged_port_start`（内核默认 1024，Docker 默认 0）** 且 **`CapEff` 无 `NET_BIND_SERVICE`** → 才拒。实测：root 无位被拒、root 只留该位通过、**非 root 一律被拒** |
| 以为非 root 能靠 `--cap-add` 提权 | 非 root 时 **`CapPrm`/`CapEff` = 0**，`--cap-add` 只写进 `CapBnd`（天花板）→ **不生效**。要真拿到能力得用 file capabilities（`setcap`）或 ambient caps |
| 以为"Docker 默认 = 最小权限" | Docker 会主动放宽默认值（实测：`ping_group_range=0 2147483647` → 任何 gid 都能建 ICMP datagram socket；`ip_unprivileged_port_start=0` → 任何 uid 都能绑低端口）。`--cap-drop=ALL` 管不到这些，要显式 `--sysctl` 覆盖 |
| 用一个"被默认值短路"的命令去测能力位 | 没控制 sysctl 的实验会四组全成功（实测踩过）。测前后都先 `cat /proc/sys/net/ipv4/...` 量一下底料 |

### 10.3 `sh -c` 什么时候才需要

| 写法 | 容器里 PID 1 是谁 | 什么时候用 |
|---|---|---|
| `docker run ... alpine ping -c1 8.8.8.8` | `ping` | 单条命令 → **exec 形式，推荐** |
| `docker run ... alpine sh -c 'a && b'` | `sh` | 需要**多命令 / 管道 / 重定向 / 变量 / 通配符**时 |

⚠️ 用了 `sh -c`，PID 1 就变成 shell → 信号要先过 shell 这一关（Day 5 的信号实验：PID 1 不装 handler 时 SIGTERM 会被内核忽略）。

### 10.4 `-f '{{...}}'` 是 Go 模板

| 片段 | 含义 |
|---|---|
| `-f` / `--format` | 只输出模板算出来的东西，不吐整坨 JSON |
| `.` | `inspect` 返回的那个对象本身 |
| `{{.State.ExitCode}}` | 字段路径，逐级用 `.` 连接 |
| 常用 | `{{.State.OOMKilled}}` `{{.State.Error}}` `{{.Config.User}}` `{{.Config.Env}}` `{{.HostConfig.Memory}}` |
