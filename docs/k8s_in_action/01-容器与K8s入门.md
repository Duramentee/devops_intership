# 模块 01 · K8s 是什么 + 容器与镜像（第 1~2 章）

> 目标：搞懂「为什么需要 K8s」，亲手打包一个应用并在集群里跑起来。

## 一、核心概念（整体观）

### 1. 为什么从单体走向微服务（p.36-42）

| 架构 | 优点 | 缺点 |
|---|---|---|
| 单体 | 部署简单 | 一处改动全量部署、难扩展（数据库等难水平扩展）、复杂度堆积 |
| 微服务 | 独立开发/部署/扩容 | 组件变多后配置与部署的组合爆炸，难管理 |

→ 于是需要一种方式：让开发者自己部署、不用关心硬件，让运维只关心基础设施。这就是 K8s（NoOps 理念，p.42）。

### 2. 容器 vs 虚拟机（p.43-54）

| 维度 | 虚拟机 | 容器 |
|---|---|---|
| 隔离机制 | 每个 VM 有自己内核 | 共享宿主机内核，用**命名空间**隔离视图、**cgroups** 限制资源 |
| 开销 | 跑一套系统进程，重 | 只是一个被隔离的进程，轻 |
| 启动 | 像开机，慢 | 极快 |
| 安全 | 更强 | 共享内核，弱一些 |
| 可移植性限制 | 无 | 依赖宿主机**内核版本**和**硬件架构**（x86 镜像不能在 ARM 跑）|

**两个隔离机制**（p.47-48）：
- **Linux 命名空间**：让进程只看到自己的文件/进程/网络接口/主机名等。类型：Mount、PID、Network、IPC、UTS、User。
- **cgroups**：限制进程能用的 CPU/内存/网络带宽。

### 3. Docker 三大概念（p.49-50）

- **镜像**：打包了应用 + 依赖 + 文件系统的只读模板
- **镜像仓库**：存镜像的地方（Docker Hub 等）
- **容器**：基于镜像创建的、被隔离的、资源受限的运行中进程

**镜像分层**（p.53）：镜像由多层构成，层可共享；层是**只读**的，容器运行时在顶层加一个**可写层**（写入时复制，copy-on-write）。

### 4. Kubernetes 架构（p.57-59）

```
控制平面（大脑）：API server、Scheduler 调度器、Controller Manager、etcd
工作节点（干活）：容器运行时(Docker)、Kubelet、kube-proxy
```

- 开发者把应用描述提交给 **API server** → 调度器选节点 → Kubelet 让容器运行时拉镜像、跑容器。
- 你**不关心**应用跑在哪台机器上。

### 5. K8s 的好处（p.61-65）

简化部署、更好利用硬件、健康检查与自修复、自动扩容、简化开发（服务发现/leader 选举不用自己做）。

## 二、关键细节

- 运行一个 K8s 应用的三步（p.59）：打包成镜像 → 推送到仓库 → 把描述提交给 API server。
- `kubectl run` 幕后（p.92-94）：kubectl → API server（存 etcd）→ RC 创建 Pod → 调度器选节点 → Kubelet 通知 Docker 拉镜像跑容器。
- 水平伸缩（p.99-101）：改期望副本数，声明式地让 K8s 把当前状态对齐到期望状态。

## 三、命令速查

| 场景 | 命令 | 说明 |
|---|---|---|
| 跑个 hello | `docker run busybox echo "Hello world"` | 自动拉取并运行 |
| 构建镜像 | `docker build -t kubia .` | 基于 Dockerfile，当前目录 |
| 后台运行+映射端口 | `docker run --name kubia-container -p 8080:8080 -d kubia` | `-d` 后台，`-p` 映射 |
| 看容器 | `docker ps` / `docker ps -a` | 运行中 / 含已停止 |
| 看底层信息 | `docker inspect <容器>` | 长 JSON |
| 进容器 | `docker exec -it kubia-container bash` | `-i` 交互 `-t` 终端 |
| 停止/删除 | `docker stop` / `docker rm` | 停止主进程 / 真删除 |
| 打标签 | `docker tag kubia luksa/kubia` | 同一镜像加别名 |
| 推送 | `docker push luksa/kubia` | 需先 `docker login` |
| 启动本地集群 | `minikube start` | 单节点 |
| 看集群 | `kubectl cluster-info` / `kubectl get nodes` | API 地址 / 节点 |
| 部署应用 | `kubectl run kubia --image=luksa/kubia --port=8080` | 现代版本默认建 Deployment |
| 对外暴露 | `kubectl expose ... --type=LoadBalancer` | 分配外部 IP |
| 伸缩 | `kubectl scale ... --replicas=3` | 改期望副本数 |
| 看 IP 和节点 | `kubectl get pods -o wide` | 多 IP、NODE 列 |

## 四、易错点

1. 构建目录别放大文件——整个目录会上传给 Docker 守护进程（p.73）。
2. Dockerfile **每条指令**都新建一层，不是整个文件一层（p.73）。
3. Minikube 不支持 LoadBalancer 拿外部 IP，用 `minikube service <svc>` 访问（p.95）。
4. K8s 不会让你的应用自动可扩展，应用本身要支持水平伸缩（p.100）。

## 五、动手实践（本周完成）

1. 写一个 `app.js`（HTTP 返回 hostname），写 Dockerfile：
   ```dockerfile
   FROM node:7
   ADD app.js /app.js
   ENTRYPOINT ["node", "app.js"]
   ```
2. `docker build -t kubia .` → `docker run -p 8080:8080 -d kubia` → curl 验证。
3. `minikube start` → `kubectl run kubia --image=kubia --port=8080` → `kubectl expose deployment kubia --type=NodePort` → `minikube service kubia` 访问。
4. `kubectl scale deployment kubia --replicas=3`，观察 `kubectl get pods -o wide` 多出两个 pod。
