# 模块 08 · 开发最佳实践与扩展机制（第 17~18 章）

> 目标：让应用"经得起折腾"（随时被杀/迁移也能优雅收尾），并知道怎么扩展 K8s 本身。

## 一、核心概念（整体观）

### 1. 典型应用资源全景（p.724-725）

一个规范的 K8s 应用 = `Deployment/StatefulSet` + 存活/就绪探针 + `Service/Ingress` + `Secret/ServiceAccount` + `ConfigMap` + 卷 + `Job/CronJob`；管理员侧再加 `DaemonSet`、`HPA`、`LimitRange`、`ResourceQuota`。

### 2. Pod 生命周期（p.727-742）

- Pod 会被随时杀死、重调度，IP/名字/主机名都会变——**不要依赖 IP**；只有 StatefulSet 保证主机名和持久状态。
- **优雅关闭链路**：删 Pod → 设 `deletionTimestamp` → Kubelet 执行 preStop 钩子 → 发 SIGTERM → 等终止宽限期（默认 **30 秒**）→ 超时 SIGKILL。
- **init 容器**：`spec.initContainers` 顺序执行，全完成才启动主容器；用于初始化、写数据到卷、等依赖服务就绪。
- **生命周期钩子**（容器级）：`postStart`、`preStop`。

### 3. 可管理性三件套（p.753-760）

- **日志写标准输出**（`kubectl logs` 能看）；写文件则要 `kubectl exec/cp` 手动取。
- **镜像打版本标签**，别用 `latest`（新旧版本不一致、无法回退）。
- **多维度标签**（如 app/rel/tier）+ 注解描述资源。

### 4. 扩展 K8s（p.770-805）

| 机制 | 作用 |
|---|---|
| CRD | 提交一个对象就注册新资源类型，**无需改 API server 代码** |
| 自定义控制器 | 监听自定义对象并落地动作（CRD 本身**不产生任何动作**）|
| API 聚合 | 多个 API server 挂到同一入口，客户端无感知 |
| 服务目录 Service Catalog | 标准 API 自助调配外部服务 |
| Helm | K8s 包管理器（chart 打包应用）|

## 二、关键细节

- 删除 Pod 有两条并行事件链：① API server→Kubelet 发 SIGTERM；② API server→Endpoint 控制器→kube-proxy 更新 iptables。**iptables 规则移除不影响已建立连接**，所以 SIGTERM 常先到（p.748-749）。
- 正确关闭顺序：收到终止信号 → 等几秒 → 停止接新连接 → 关空闲长连接 → 等现有请求完成 → 退出。
- **SIGTERM 被 shell 吞掉**：Dockerfile 用 shell 形式 `ENTRYPOINT /mybinary` 时信号到不了应用；改用 exec 形式 `ENTRYPOINT ["/mybinary"]`。
- 容器崩溃**不会**触发重新调度（RS 只看数量）；重启间隔指数增长到 5 分钟。
- 控制器 watch 会漏事件，正确实现要定期重新 list。
- 校验应放在 API server 侧（`CustomResourceValidation` + JSON schema），不要放控制器里（用户收不到错误）。

## 四、易错点

1. 写容器文件系统的数据**重启即丢**（全新可写层）；要跨容器用 pod 级卷，但卷损坏会持续 CrashLoopBackOff。
2. 就绪探针解决不了关闭断连——deletionTimestamp 一设，Endpoint 就被移除；要收到 SIGTERM 后**再等几秒**才停接连接。
3. `latest` 标签的坑：重调度后新旧版本混布、无法回退。
4. CRD 本身不产生动作，必须配套控制器。
5. CRD 长名（`websites.extensions.example.com`）≠ kind（`Website`），建实例用 `names.kind`。
6. 服务目录不自动注入凭证，Pod 要手动挂 Secret。

## 五、动手实践（含全书综合实战）

1. 给 Pod 加 preStop 钩子（`sleep 5`）+ 优雅关闭逻辑，`kubectl delete pod` 观察 SIGTERM→宽限期→退出的顺序（`kubectl logs`）。
2. 写一个 init 容器（等主服务就绪再启动主容器），理解 init 顺序。
3. 注册一个 CRD，`kubectl get` 列出自定义资源；再理解"没有控制器它什么也不做"。
4. **综合实战**：把一个完整应用（前端+后端）用所学全部手段部署：Deployment + 就绪/存活探针 + Service/Ingress + ConfigMap/Secret + PVC + requests/limits + HPA + 优雅关闭，并做一次滚动升级和回滚。
