## 1. 第 1 段 · Shell 主域（错题本 L7～L9）

### 1.1 闭卷作答与核对

| 题号 | 我闭卷写下的答案 | 核对结果 |
|---|---|---|
| 1 | 「shell 在真正执行命令之前会先经过预处理阶段，会走 IFS 分词、glob 分词以及通配符展开」 | 方向正确，术语与归类错误。① 准确名称是**展开（expansion）**，不是笼统的「预处理阶段」，「预处理」也不是 shell 的术语；② 「glob 分词」与「通配符展开」是同一件事被写了两遍，标准名称是 **pathname expansion（路径名展开）**，并且它**不是一种分词**；③ 未答出**切分者、切分时机、分隔符**这三个要点 |
| 2 | 未作答 | 见 §1.2 |
| 3 | `for f in "/data*"; do cp -- "$f" /backup/; done` | `cp -- "$f" /backup/` 这一句正确；`for f in "/data*"` 有两处错误：① 双引号**阻止了 pathname expansion**，`*` 根本没有展开，`f` 只取到字面量 `/data*`，循环只执行一次；② 路径写成 `/data*`，匹配的是以 `/data` 开头的条目（例如 `/database`），而不是 `/data` 目录**里面**的条目。另外缺少「模式不匹配任何条目」时的判断 |

### 1.2 第 1 题与第 2 题的正确结论

| 要答的点 | 结论 |
|---|---|
| **谁**在切分 | **shell**。`ls` 只负责把文件名打印成一段文本，它不参与切分 |
| 切分发生在**哪个时机** | 在**命令替换完成之后**：`$(ls /data)` 先把 `ls` 的输出捕获成一段文本，shell 再对这段文本做 word splitting |
| 按**什么**切分 | 按 `IFS`（Internal Field Separator）。默认取值是**空格、制表符、换行**三个字符，**不含**逗号与冒号 |
| 对 `a b.txt` 的后果 | `ls` 的输出里文件名既含空格又被换行分隔，于是被切成 `a` 与 `b.txt` **两个词**；`for` 循环两次，`f` 依次取到 `a` 与 `b.txt`；`cp a /backup/` 因找不到名为 `a` 的文件而报错，真正的文件 `a b.txt` **从未被复制** |
| 第二次切分在哪里 | 在循环体 `cp $f /backup/` 的 `$f`。它没有加引号，先做参数展开，再**被切分一次**，随后还会做 pathname expansion。只要 `f` 的取值本身含空格，就会被再切成多个参数 |
| 分词之后还会执行哪一种展开、基准目录是哪里 | **pathname expansion（路径名展开，glob）**；基准目录是**当前工作目录**，不是变量里那个文件的所在目录 |

### 1.3 展开顺序（bash）

| 顺序 | 展开名称 | 作用 |
|---|---|---|
| 1 | brace expansion（大括号展开） | 把 `{a,b}` 展开成多个词 |
| 2 | tilde expansion（波浪号展开） | 把 `~` 换成家目录 |
| 3 | parameter / variable expansion（参数与变量展开）、command substitution（命令替换）、arithmetic expansion（算术展开） | 三者从左到右依次执行 |
| 4 | **word splitting（分词）** | 对**未加引号**的第 3 步结果，用 `IFS` 切分成多个词 |
| 5 | **pathname expansion（glob）** | 对每个词，若含 `*`、`?`、`[`，则在**当前工作目录**下展开成匹配的文件名 |
| 6 | quote removal（引号移除） | 去掉引号本身 |

### 1.4 第 3 题的正确结构与三条边界

```bash
for f in /data/*; do
    [ -e "$f" ] || continue
    cp -- "$f" /backup/
done
```

| 要满足的条件 | 做法与机制依据 |
|---|---|
| 不漏文件 | 遍历来源使用 glob `/data/*`，由 shell 在 pathname expansion 阶段展开成目录内的全部条目 |
| 含空格的文件名不被拆开 | glob 展开得到的每个文件名**各自成为一个独立的词**，并且 glob 的结果**不再参与分词**；循环体内再对变量 `"$f"` 加引号，阻止第二次切分 |
| `-dash` 不被当成选项 | `cp -- "$f" /backup/` 里的 `--` 让后面的参数不再被解析成选项 |
| 目录为空或多个模式不匹配时的处理 | 这一项取决于具体的 shell。**bash** 默认把不匹配的模式**原样保留**成字面量留在词表里，循环仍执行一次，因此需要 `[ -e "$f" ] \|\| continue` 跳过该次循环；**zsh** 默认开启 `nomatch` 选项，模式不匹配时直接报 `no matches found: *` 并**中止整条命令**，循环一次都不会执行（实测见 §2.3 段 D）。因此在 zsh 中要么执行 `setopt NULL_GLOB`，要么同时保留 `[ -e "$f" ] \|\| continue` 以兼容两种 shell |

> 引号的两个作用：双引号与单引号**同时**阻止 word splitting 与 pathname expansion。由此得到规则：**引号只包变量，不包通配符**。要遍历某个变量所指目录里的条目时，写成 `for f in "$dir"/*`，引号只包住 `$dir`，`/*` 留在引号之外。

### 1.5 L8 与 L9 的正确结论

| 编号 | 正确结论 |
|---|---|
| L8 | `awk` 本身可以直接读取文件，写成 `awk '{print $1}' /var/log/nginx/access.log`。`cat 文件 \| awk ...` 多产生一个进程与一次管道数据拷贝，**不改变结果**、只增加开销，这种写法称为 UUOC（useless use of cat），因为「结果对」不等于「写法对」，所以最难被自查发现 |
| L9 | `uniq` **只比较相邻行**，同一取值只要不连续就会被**分别计数**。`sort` 的唯一作用是把相同行**排到相邻**，而不是让 `uniq` 具备全局去重能力。更省一次排序的写法是 `awk '{c[$1]++} END{for(i in c) print c[i], i}' log \| sort -rn \| head` |

## 2. 第 2 段 · Linux 每日一题 Day 4（安全打印文件名）

题目：目录里有 `a b.txt`、`*star*`、`-dash`、`normal.log` 四个文件，写一个 `for` 循环逐个安全打印它们。

### 2.1 执行前的预测

| 序号 | 预测 | 依据 |
|---|---|---|
| 1 | `for f in *` 由 shell 在 pathname expansion 阶段把 `*` 展开成四个文件名，每个文件名各自成为一个词，循环执行四次 | glob 的结果不再参与分词 |
| 2 | `f` 取到 `a b.txt` 时是一个完整的词，循环体写成 `"$f"` 就会原样打印 | 引号阻止第二次分词 |
| 3 | `f` 取到 `*star*` 时，若循环体写成未加引号的 `$f`，该取值会被再次当作通配模式展开 | 未加引号的变量取值仍要经过 pathname expansion |
| 4 | `f` 取到 `-dash` 时，只要它处在非选项位置就不会被当成选项 | 选项解析只看第一个参数是否以 `-` 开头 |
| 5 | 若改成 `for f in $(ls)`，`a b.txt` 会被切成 `a` 与 `b.txt` 两个词 | 第 1 段已确认命令替换的输出经过 word splitting |

### 2.2 最小复现命令

```bash
rm -rf /tmp/day4 && mkdir -p /tmp/day4 && cd /tmp/day4
: > 'a b.txt'; : > '*star*'; : > '-dash'; : > normal.log
ls -1
for f in *; do printf '%s\n' "$f"; done
for f in $(ls); do printf '%s\n' "$f"; done
mkdir -p /tmp/day4e && cd /tmp/day4e
for f in *; do printf '[%s]\n' "$f"; done
```

### 2.3 实测输出

```text
=== A: ls -1 ===
a b.txt
-dash
normal.log
*star*
=== B: for f in * ; printf ===
a b.txt
-dash
normal.log
*star*
=== C: for f in $(ls) ===
a
b.txt
-dash
normal.log
*star*
=== D: empty dir, for f in * ===
zsh: no matches found: *
```

### 2.4 预测与实测对账

| 预测 | 实测 | 判定 |
|---|---|---|
| 1 | 段 B 打印四行，文件名与段 A 的 `ls -1` 一致 | 通过 |
| 2 | 段 B 第一行是完整的 `a b.txt` | 通过 |
| 3 | 本次没有在目录里再构造一个名字含 `star` 的文件，因此这一条只保留了机制说明，没有取得对照证据 | 待补 |
| 4 | 段 B 第二行打印出 `-dash`，没有被解析成选项 | 通过 |
| 5 | 段 C 第一行与第二行分别是 `a` 与 `b.txt`，确认命令替换的输出被按空格切开 | 通过 |
| 空目录（本次预测之外） | 段 D 报 `zsh: no matches found: *`，**循环一次都没有执行** | **与 bash 的预期不符，属于预测之外的发现** |

### 2.5 由本次实测得到的硬结论

| 条件句 | 证据 |
|---|---|
| 当 shell 执行 `for f in *` 时，`*` 的展开者是 **shell**，展开发生在循环开始之前，`for` 收到的已经是展开后的文件名列表 | 段 B 打印的文件名与顺序和段 A 的 `ls -1` 一致 |
| 当遍历来源是 glob 时，含空格的文件名各自成为一个独立的词，循环体再对变量加引号即可完整打印 | 段 B 第一行输出完整的 `a b.txt` |
| 当遍历来源是 `$(ls)` 时，文件名中的空格会被当作分隔符切开 | 段 C 把 `a b.txt` 拆成 `a` 与 `b.txt` 两行 |
| 当 shell 是 zsh 且模式不匹配任何文件时，`for f in *` 报 `no matches found` 并中止整条命令，循环体一次都不执行 | 段 D 的实测输出 |
| 当需要「模式不匹配时不报错也不执行循环」时，zsh 需要 `setopt NULL_GLOB`；写 `[ -e "$f" ] \|\| continue` 则同时兼容 zsh 与 bash（bash 下循环会执行一次，由该判断负责跳过） | 由段 D 的实测结果与 §1.3 的展开顺序推出 |

> ⚠️ **shell 差异（本机交互 shell 为 zsh）**：错题本 L7 中「shell 对未加引号的替换结果做 word splitting」这一条需要限定。对于 **`$(...)` 命令替换的输出**，zsh 与 bash 都会进行分词（段 C 已证实）；但对于 **变量 `$var`**，zsh 默认**不**分词（除非执行 `setopt SH_WORD_SPLIT`），而 bash 默认分词。除此之外，zsh 默认开启 `nomatch`，模式不匹配时报错中止，bash 默认保留字面量。写脚本时应当显式声明 `#!/usr/bin/env bash`，或者在使用 zsh 时显式设置上述选项，避免同一段脚本在两种 shell 下行为不同。

## 3. 第 3 段 · 四域错题抽背

| 域 | 编号 | 问题 | 按「现象 → 机制 → 判断依据」回答的要点 |
|---|---|---|---|
| Linux | L4 | nginx 日志按**每小时**统计请求数，并倒序取前 5 | 用**一次遍历 + 关联数组**：`awk '{split($4,t,":"); c[t[2]]++} END{for(h in c) print c[h],h}' log \| sort -rn \| head -5`。机制依据是 `uniq -c` **只合并相邻行**，同一取值不连续就会被分别计数；`sort` 的唯一作用是把相同行排到相邻，不能靠 `uniq` 本身实现全局去重 |
| Docker | D6 | Docker 层缓存与 Go 的 `GOCACHE` 如何区分 | 两套互相独立的缓存。**Docker 层缓存**由**构建器**管理，用来决定某一层是否显示 `CACHED`，它**不进入镜像**；**Go 的 `GOCACHE`** 由 **Go 工具链**管理，是编译中间产物的目录，它**会**留在执行 `RUN go build` 的那一层里 |
| Kubernetes | K25 | 从用户提交 Deployment 到容器运行，完整控制链路中调度器位于哪里 | API Server → Deployment 控制器 → **ReplicaSet 控制器**（创建 Pod 对象，此时 `spec.nodeName` 为空）→ **scheduler**（写入 `spec.nodeName`）→ kubelet → 容器运行时。调度器位于 ReplicaSet 控制器**之后**、kubelet **之前** |
| CI/CD | CI2 | 一个 job 的文件能否被另一个 job 直接读取；`needs` 与 artifact 分别做什么 | 不能。每个 job 使用**独立的执行器与独立的工作区**。`needs` 只建立**执行顺序与成功条件**，它**不传递文件**；跨 job 传文件必须用 **artifact** 的显式上传与下载，少量元数据可以用 job outputs |

## 4. 第 4 段 · 域外口述（摘自 `notes/week2/提炼-反例与关系.md`）

| 域 | 条目 | 回答要点 |
|---|---|---|
| Kubernetes | 条件句第 24 条（启动探针） | 配置启动探针之后，在它**第一次成功之前**，存活探针与就绪探针都**不会执行**。允许的最长启动时间由 `failureThreshold` 与 `periodSeconds` 的乘积决定，严格写法是 `initialDelaySeconds + failureThreshold × periodSeconds`。机制依据：kubelet 先用启动探针判断容器是否已经启动完成，只有它成功之后才启用另外两种探针，这样就不会把「启动慢」误判成「运行中故障」 |
| Docker | 错题 D18（绑低端口的判定） | 拒绝绑定的判定需要**两个条件同时成立**：① 端口号小于 `ip_unprivileged_port_start`；② 进程的有效能力集合 `CapEff` 中**没有** `NET_BIND_SERVICE`。两个条件之间是「与」关系，任一条件不成立就允许绑定。只写 `--cap-add` 而不加 `--sysctl` 时：Docker 交给容器的 `ip_unprivileged_port_start` 默认取值为 `0`，因此「端口号小于 0」永远为假，第一个条件不成立，于是 443 也能绑上。要复现拒绝，必须先用 `--sysctl net.ipv4.ip_unprivileged_port_start=1024` 把阈值抬到 1024 |
