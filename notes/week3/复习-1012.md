|---|---|---|---|---|---|
| A1 | 用一条命令证明两个文件指向同一 inode；`rm` 掉其中一个之后，另一个的链接计数与 inode 号如何变化 | 链接计数减一、inode 号不变 | `source.txt` 与 `target_hard` 同属 inode `20492`、链接计数为 `2`；`rm target_hard` 之后链接计数变为 `1`，inode 号仍然是 `20492` | `rm` 只删除一条目录项，并使该 inode 的链接计数减一；链接计数未归零，因此数据块继续保留 | `ls -li`、`stat` |
| A2 | 同一组文件分别改成软链接，重复 A1 | 初始预测「链接计数与 inode 号都不变，`cat` 读到路径字符串」 | 创建软链接没有增加目标文件的链接计数（`source.txt` 的计数始终为 `1`）；软链接自身 inode 为 `22582`（不等于 `20492`）、类型为 `l`、`size` 为 `10`（等于路径字符串 `source.txt` 的长度）；`cat target_soft` 输出目标内容 `something` | 内核打开符号链接时自动跟随到目标文件；路径字符串只能用 `ls -l`、`readlink` 或 `stat` 查看，不能用 `cat` 输出 | `ls -li`、`readlink` |
| A3 | 构造「`df` 显示已用接近 100%，而 `du` 合计只有一半」的状态，并定位到具体文件 | `lsof +L1` 定位；关闭 fd 之后 `df` 变小、`du` 基本不变 | `lsof +L1` 列出 `zsh 2372 3r REG 209715200 NLINK 0 ... big.bin (deleted)`；`rm` 之后 `du -sh .` 从 `201M` 降到 `4.0K`；用 `df -BK .` 重测后，`Used` 由基线 `17038024K` 升到 `17242824K`（差 `204800K`，等于 `200M`），持有 fd `4` 期间保持 `17242824K` 不变，关闭 fd 后回落到 `17038024K` | `du` 递归遍历目录项求和，`df` 读取超级块中的已分配块；fd 仍引用该 inode 时块不释放 | `lsof +L1`、`du -sh`、`df -BK` |
| A4 | 构造一个僵尸进程，说明它为什么无法被信号消灭、真正的处理动作是什么 | `STAT` 显示为 `Z`、`kill -9` 不起效 | 僵尸为 PID `14574`、PPID `14569`、`STAT` 为 `ZN`；`kill -9 14574` 返回成功但进程仍然存在；结束父进程 `14569` 之后，僵尸被 PID 1 回收 | 僵尸进程已无可执行代码，信号不会被任何代码处理；回收只能由父进程调用 `wait()` 完成，父进程先退出时由 PID 1 收养并回收 | `ps -eo pid,ppid,stat,cmd` |
| A5 | 目录的 `x` 位与 `r` 位分别控制什么；构造只有 `r` 没有 `x` 的目录，记录 `ls`、`ls -l`、`cat` 三种操作的结果 | 初始预测「`x` 控制目录内部与写操作、`r` 控制读目录、`r` 不允许 `ls`」（把 `w` 与 `x` 混淆） | 保留 `r` 去掉 `x`（`drw-r--r--`）时 `ls ./tmp` 列出名称 `1.txt 2.txt` 并伴随 `cannot access` 报错、`ls -l ./tmp` 对条目显示 `?` 与 `cannot access`、`cat ./tmp/1.txt` 失败；只保留 `x`（`d--x--x--x`）时 `ls` 报 `cannot open directory`、`cat ./tmp/1.txt` 成功输出 `something` | 列出名称使用 `readdir`，只需要 `r` 位；对条目做 `stat` 或 `open` 需要把目录当作路径的一段穿越，也就是需要 `x` 位；创建与删除条目需要 `w` 位并且需要 `x` 位 | `ls`、`ls -l`、`cat` |

## 5. 结论与新确认的边界条件

> 只写「反推出的机制」「被实测推翻的说法」「新确认的限定条件」，每条写成条件句。

| 编号 | 条件句 | 依据（命令输出 / 字段） |
|---|---|---|
| 1 | 当一个 inode 的链接计数大于 0 时，删除其中一条目录项只会让链接计数减一，数据块不会释放；只有当链接计数为 0 且没有任何进程持有 fd 时，数据块才释放 | A1：`source.txt` 与 `target_hard` 共用 inode `20492`，`rm` 后计数由 `2` 变为 `1`、inode 号不变 |
| 2 | 创建符号链接不会增加目标文件的链接计数；符号链接自身拥有独立 inode，内容是目标路径字符串；读取符号链接时内核跟随该链接并输出目标文件的内容 | A2：软链接 inode `22582`、`size` 为 `10`、`cat` 输出 `something` |
| 3 | 当文件已被 `rm` 但仍有进程持有它的 fd 时，`du` 因为不再遍历到该目录项而立刻变小，`df` 因为该文件的块仍被引用而不变；只有当最后一个 fd 关闭或持有进程退出时，`df` 才回收这部分块 | A3：`lsof +L1` 显示 `NLINK 0`，`du` 由 `201M` 变为 `4.0K`；`df -BK .` 的 `Used` 由 `17038024K` 升到 `17242824K`，持有 fd 期间不变，关闭 fd 后回落 |
| 4 | 僵尸进程无法被任何信号消灭，因为进程退出后已不存在可被信号处理的代码；回收动作只能由父进程调用 `wait()` 完成，父进程先退出时由 PID 1 收养并回收 | A4：`kill -9 14574` 之后 `STAT` 仍为 `ZN`；结束父进程后僵尸被回收 |
| 5 | 当目录只具备 `r` 位而缺少 `x` 位时，`ls` 可以列出条目名称，但任何需要 `stat` 条目属性的操作都会失败；当目录只具备 `x` 位而缺少 `r` 位时，`ls` 与 `ls -l` 失败，而按已知完整路径访问条目成功 | A5：`drw-r--r--` 与 `d--x--x--x` 两种模式下的 `ls`、`ls -l`、`cat` 对照 |

## 7. 十分钟速记卡

| 项目 | 内容 |
|---|---|
| 一句话主线 | 命令的输出是「给人看的文本」还是「给程序用的列表」，决定了能不能直接参与循环与管道 |
| 必须记住的机制 | 目录项与 inode 的分工、链接计数、文件描述符、`df` 的统计口径与 `du` 的遍历口径 |
| 全流程链路摘要 | shell 解析 → 分词与展开 → 内核创建进程 → 程序读取文件或目录项 |
| 本次实测得到的硬结论 | 当文件已被 `rm` 但仍有进程持有它的 fd 时，`du` 立即变小而 `df` 暂时不变；实测证据是 `lsof +L1` 中该文件的 `NLINK` 为 `0`、`du -sh .` 由 `201M` 变为 `4.0K`、`df -BK .` 的 `Used` 在持有 fd 期间保持 `17242824K` 不变而关闭 fd 后回落至 `17038024K`。同一个 inode 上的两条目录项共用链接计数，实测中 `source.txt` 与 `target_hard` 共用 inode `20492`，删除其中一条后计数由 `2` 变为 `1` |
| 出现异常时的排查顺序 | 先判断是「命令写错」还是「数据被分词/展开破坏」，再判断是「对象层」还是「数据层」 |
| 最容易答错的点 | 把现象当成机制（只描述「出错了」，不说「谁在做、按什么规则做」）；把软链接的 `cat` 当成读取路径字符串；把目录的 `x` 位职责与 `w` 位混为一谈 |
| 合上笔记自测 | ① 硬链接的链接计数何时减一、数据何时才真正释放？② `df` 与 `du` 不一致的两个常见原因？③ 目录的 `r` 位与 `x` 位各控制什么？ |
