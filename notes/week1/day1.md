## 概念

> 五条机制，把 Linux/Shell 的"为什么"钉住。答错的题基本都能归到其中一条。

1. **文件 = inode + 目录项**。文件名只是目录里一条「名字 → inode」记录；数据、权限、大小、时间戳都挂在 inode 上。
   - **硬链接** = 再添一条目录项指向同一 inode，链接计数 +1；删掉一个名字只是计数 -1，数据还在 → `cat hard.txt` 正常。
   - **软链接** = 一个独立文件，**内容是路径字符串**；路径没了就断链 → `cat soft.txt` 报 No such file。
   - 硬链接不能跨文件系统、不能指向目录；软链接都可以。
2. **Shell 的三层展开**（这次错得最多的根源）：变量/命令替换 → **按 IFS 分词** → **通配符展开**，全部发生在命令执行**之前**。所以 `$(ls)` 的结果会被再拆一次 → `for f in $(ls)` 会碎。
3. **磁盘空间 ≠ 文件大小之和**。目录项删了但**进程还持着 fd**，空间不释放（`lsof +L1` 的经典场景）；`du` 也看不到被挂载点覆盖的目录，且 `du -sh /*` **不含以 `.` 开头的目录**，非 root 还会跳过没权限的目录（`2>/dev/null` 一加就"变小"了）。
4. **进程生命周期**：`fork` 生子 → 子进程 `_exit` 退出但**父进程没调 `wait()`** → 子进程变僵尸（`Z`/`defunct`），只剩一条进程表项（pid + 退出状态）；父进程 wait 后回收；父进程先死则由 init/systemd 收养回收。僵尸**杀不掉**（已经死了）。
5. **awk 是一次遍历 + 关联数组聚合**。「按某字段分组计数」是它的主场，别再用 `grep | sort | uniq -c` 套娃（而且 `uniq` 只合并**相邻**重复，忘了 `sort` 结果必错）。

## 命令

| 场景 | 命令 | 说明 |
|---|---|---|
| 看 inode 与链接数 | `ls -li` | 硬链接两者 inode 相同、链接数 ≥2；软链接是独立 inode 且显示 `->` |
| 建链接 | `ln a b` / `ln -s a b` | 加 `-s` 才是软链接 |
| 按条件找文件 | `find /data -type f -name '*.tar.gz' -mtime +30 -size +50M` | 路径只给目录；**通配符交给 `-name`**，加引号防 shell 展开 |
| 先预览再删 | `find ... -print` 跑一次确认，再把 `-print` 换成 `-delete` | 生产习惯，避免误删 |
| 三种批量删除 | `-exec rm {} \;` / `-exec rm {} +` / `-delete` | 逐个 fork / 批量一次 fork / 不 fork（最快，隐含 `-depth`，不能配 `-prune`） |
| 安全遍历目录 | `for f in "$dir"/*; do [ -e "$f" ] \|\| continue; ...; done` | 绕开 `$(ls)` 的分词坑 |
| 查"被删还占着空间"的文件 | `lsof +L1` | 磁盘满但 `du` 对不上的第一招 |
| 按小时统计日志 | `awk '{split($4,t,":"); c[t[2]]++} END{for(h in c) print c[h], h}' access.log \| sort -rn \| head -5` | 一次遍历聚合，不需要循环 |

## 易错点

| 错法 | 现象 | 正确做法 |
|---|---|---|
| `find "/data/*.tar.gz"` | 找不到东西：引号让 **shell 不展开**，而 find **不会**展开路径里的通配符 | `find /data -type f -name '*.tar.gz'` |
| `-mtime +30d`、`-size +50m` | 部分实现报 `invalid argument`；单位后缀在 `-mtime` 上不可移植，`-size` 的正规后缀是大写 `M`/`G` | 写 `-mtime +30`、`-size +50M` |
| `for f in $(ls)` | 文件名含空格/换行/`*` 时被拆成多个，逻辑全乱 | `for f in "$dir"/*` + `[ -e "$f" ]` 守卫 |
| 以为"空目录会让 `$(ls)` 报错" | **说反了**：空目录时循环体一次都不执行、不报错；真正会出错的是 `for f in *` 在无匹配时迭代字面量 `*` | 加 `[ -e "$f" ] \|\| continue` |
| `rm $file` | 变量被分词 + 通配符展开，含空格的文件名拆成多个参数 → 可能删错对象（不是"被当命令"，是"被当**多个参数**"） | `rm "$file"`（除非有意分词） |
| `cat f \| awk ...` | 多一个无用进程 | `awk '...' f` |
| `awk ... \| uniq -c` | 结果错：`uniq` 只合并**相邻**重复 | 先 `sort` 再 `uniq -c`，或直接用 awk 关联数组 |

1. cat hard.txt 能获得预期结果, 获得的结果和执行 rm a.txt 所获得的结果一致, 而执行 cat soft.txt则会报错, 原理是: 硬链接本质上是为文件背后的inode起了一个新名字, 所以删去a.txt不会报错, 而软连接则是存了一份a.txt的路径, 原文件a.txt没了自然就报错了
2.  `find "/data/*.tar.gz" -mtime +30d -size +50m -exec rm -f {} +` , `-exec rm {} \;`是比较老的写法, 会执行一个迭代, 每次适用的对象是{}这个占位符对应内容, 执行的动作就是rm, `-exec rm {} +` 则是一次性导入, 效率更高一点, -delete应该是-exec rm {} +的快捷写法吧, 我记不清了, 这也是一个删除操作
3. 第一个问题我记不清了, 不过 for f in $(ls) 这个指令执行的话, 如果ls的目标是一个空目录应该会迭代空内容导致错误, 怎么改正我不清楚, 或许可以先检查一下要ls的目录是否为空, `rm $file` 和 `rm "$file"` 前者没有双引号, 那么如果有空格或者其他的特殊分隔符可能会引发意外错误, 导致某些部分被当作一个命令, 而不是变量内容这一个整体, 后者则是更正确而且健壮性更好的写法
4. 这个问题我不清楚, 可能是 日志文件占用过高之类的
5. 僵尸进程是父进程还在但是子进程死了的情况, 执行ps的话, 进程状态那部分会显示Z, 虽然没有实际占用内存和cpu时间, 但是占用了pid, 所以父进程应该把子进程回收, kill -9 是强制杀死, 应该是解决不了, 因为她本身已经是一个死进程了
6. 假定nginx的日志存储为 /tmp/log/nginx.log 那么命令可以是: `cat /tmp/log/nginx/nginx.log | awk '{}' | uniq -c | tail -5`, awk中间那部分不清楚语法了, 我不知道怎么算每小时请求数, 或许可以用一个循环for i in (24), 然后awk里取到变量`[$time_local]` 也就是第 4 字段, 然后 [[ $time_local -ge i && $ $time_local -le (( i + 1 )) ]], 之后传给 wc 统计请求数

## 纠错回执（2026-09-11）

| 题 | 判定 | 关键修正 |
|---|---|---|
| 1 硬链接/软链接 | ✅ 8/10 | 机制说对了，补一个词：**链接计数**。删名只是计数 -1，inode 和数据仍在 |
| 2 find 删文件 | ⚠️ 4/10 | 三处语法错：路径不该带通配符、`+30d`/`+50m` 不可靠、缺 `-type f`。`-delete` 不是"快捷写法"，是内置动作：不 fork、隐含 `-depth` |
| 3 `$(ls)` 与引号 | ⚠️ 5/10 | 引号那半答对（但"被当命令"应为"被当**多个参数**"）；`$(ls)` 的坑是**分词/展开**，不是空目录——空目录**不报错**，循环体一次都不跑 |
| 4 df 与 du 对不上 | ❌ 2/10 | 你猜的"日志"其实**沾边**：标准答案是「日志被 `rm` 了但进程还持有 fd」→ `lsof +L1` |
| 5 僵尸进程 | ✅ 8/10 | 说对核心。精确表述：**子进程已退出，父进程未 `wait()` 回收**；若父进程先死，init 会收养，就不会变僵尸 |
| +1 awk 按小时统计 | ❌ 2/10 | 缺 `sort`（`uniq` 只合并相邻）；不会取小时字段；思路错在"用循环"——awk 一次遍历就能聚合 |

**总分 27/60**。诊断：**记忆型学习**，不是理解型。答对的两题都有机制支撑，答错的都是"背过但忘了语法"。

### 正确解法（对照抄一遍）

```bash
# 题2
find /data -type f -name '*.tar.gz' -mtime +30 -size +50M -print   # 先预览
find /data -type f -name '*.tar.gz' -mtime +30 -size +50M -delete  # 再删

# 题4
lsof +L1                    # 列出 link count = 0（已删除）但仍被打开的文件
lsof | grep -i deleted      # 等价思路

# 题6：$4 = [01/Apr/2025:10:00:00，"小时"就是第 4 字段按 : 切开的第 2 段
awk '{split($4,t,":"); c[t[2]]++} END{for(h in c) print c[h], h}' access.log | sort -rn | head -5

# 或纯 awk 输出，省一层管道（依赖日志格式，$4=`[01/Apr/2025`、$5=小时）
awk -F'[: ]' '{c[$5]++} END{for(h in c) print c[h], h}' access.log | sort -rn | head -5
```
