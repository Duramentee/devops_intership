## 1. 结论速览（5 条机制，答错的题基本都能归到其中一条）

| # | 机制 |
|---|---|
| 1 | **文件 = inode + 目录项**：文件名只是目录里一条"名字 → inode"的记录；数据、权限、大小、时间戳都挂在 inode 上 |
| 2 | **Shell 三层展开**：变量/命令替换 → **按 IFS 分词** → **通配符展开**，全部发生在命令执行**之前**。所以 `$(ls)` 的结果会被再拆一次 |
| 3 | **磁盘空间 ≠ 文件大小之和**：目录项被删但**进程仍持有 fd** 时空间不释放；`du` 也看不到被挂载点覆盖的目录 |
| 4 | **进程生命周期**：`fork` 生子 → 子进程 `_exit` 退出但父进程未 `wait()` → 子进程成为僵尸（`Z` / `defunct`），只保留一条进程表项 |
| 5 | **awk 是一次遍历 + 关联数组聚合**：「按某字段分组计数」是它的典型场景，不需要循环 |

## 2. 机制

### 2.1 inode 与两种链接

| 概念 | 机制 |
|---|---|
| 硬链接 | 再添加一条目录项指向**同一个 inode**，链接计数 +1；删除一个名字只是计数 -1，数据仍在 → `cat hard.txt` 正常 |
| 软链接 | 一个**独立文件**，其内容是**路径字符串**；目标路径不存在即断链 → `cat soft.txt` 报 `No such file` |
| 限制 | 硬链接不能跨文件系统、不能指向目录；软链接两者都可以 |

### 2.2 Shell 的三层展开（本次错得最多的根源）

展开顺序：**变量/命令替换 → 按 IFS 分词 → 通配符展开 → 去引号**，全部发生在命令执行之前。
→ `for f in $(ls)` 中，`$(ls)` 的输出会经过"分词"这一步，因此含空格的文件名会被拆成多个；而 `for f in *` 的结果由 glob 产生，**分词发生在通配符展开之前**，因此不会被再拆。

### 2.3 磁盘空间与文件描述符

| 情形 | 说明 |
|---|---|
| 目录项已删、进程仍持 fd | 空间不释放，`lsof +L1` 是排查该情形的第一手段 |
| `du` 看不到被挂载点覆盖的目录 | 挂载点下的原内容被覆盖，`du` 统计的是覆盖后的内容 |
| `du -sh /*` 不计入 `.` 开头的目录 | 隐藏目录未包含在内；非 root 还会跳过无权限目录（加 `2>/dev/null` 只是隐藏报错，统计仍然缺项） |

### 2.4 进程生命周期与僵尸进程

`fork` 生子 → 子进程 `_exit` 退出 → **父进程未调用 `wait()`** → 子进程停留在僵尸状态（`Z` / `defunct`），只剩一条进程表项（PID + 退出状态）；父进程 `wait()` 后回收；父进程先退出则由 init/systemd 收养并回收。
僵尸进程**无法通过信号处理**（进程已结束，不再被调度）。

### 2.5 awk 的聚合模型

awk 对输入做**一次遍历**，用关联数组累积结果，`END` 块输出。
→ 统计类需求不需要 `grep | sort | uniq -c` 多层管道；且 `uniq -c` 只合并**相邻**重复行，缺少 `sort` 时结果必错。

## 3. 命令

| 场景 | 命令 | 说明 |
|---|---|---|
| 看 inode 与链接数 | `ls -li` | 硬链接：inode 相同、链接数 ≥2；软链接：独立 inode 且显示 `->` |
| 建链接 | `ln a b` / `ln -s a b` | 加 `-s` 才是软链接 |
| 按条件找文件 | `find /data -type f -name '*.tar.gz' -mtime +30 -size +50M` | 路径只给目录；**通配符交给 `-name`**，加引号防止 shell 展开 |
| 先预览再删除 | `find ... -print` 跑一次确认，再把 `-print` 换成 `-delete` | 生产习惯，避免误删 |
| 三种批量删除 | `-exec rm {} \;` / `-exec rm {} +` / `-delete` | 逐个 fork / 批量一次 fork / 不 fork（最快，隐含 `-depth`，不能与 `-prune` 同时用） |
| 安全遍历目录 | `for f in "$dir"/*; do [ -e "$f" ] \|\| continue; ...; done` | 绕开 `$(ls)` 的分词问题 |
| 查"已删除但仍被占用"的文件 | `lsof +L1` | 磁盘满而 `du` 对不上时的第一手段 |
| 按小时统计日志 | `awk '{split($4,t,":"); c[t[2]]++} END{for(h in c) print c[h], h}' access.log \| sort -rn \| head -5` | 一次遍历聚合，无需循环 |

## 5. 易错点

| 错法 | 现象 | 正确做法 |
|---|---|---|
| 用 `ps -ef` 查僵尸进程并期望看到 `Z` | `ps -ef` 的固定列是 `UID PID PPID C STIME TTY TIME CMD`，**没有 STAT 列** | 用 `ps -aux`（`STAT` 在第 8 列，僵尸显示 `Z`）或 `ps -eo pid,ppid,stat,cmd` |
| `find "/data/*.tar.gz"` | 找不到文件：引号使 shell **不做展开**，而 find **不会**展开路径中的通配符 | `find /data -type f -name '*.tar.gz'` |
| `-mtime +30d`、`-size +50m` | 部分实现报 `invalid argument`；`-mtime` 不接受单位后缀，`-size` 的正规后缀是大写 `M`/`G` | 写 `-mtime +30`、`-size +50M` |
| `for f in $(ls)` | 文件名含空格/换行/`*` 时被拆成多个，逻辑全错 | `for f in "$dir"/*` + `[ -e "$f" ]` 守卫 |
| 认为"空目录会让 `$(ls)` 报错" | **说反了**：空目录时循环体一次都不执行、不报错；真正有问题的是 `for f in *` 在无匹配时迭代字面量 `*` | 加 `[ -e "$f" ] \|\| continue` |
| `rm $file` | 变量被分词 + 通配符展开，含空格的文件名会拆成**多个参数**，可能删错对象 | `rm "$file"`（除非确实需要分词） |
| 认为僵尸进程"不占内存所以无所谓" | 不占 CPU 与用户内存，但**仍占内核 `task_struct` 与 PID 表项**；大量堆积会耗尽 PID、导致 fork 失败 | 治本：父进程 `wait()` 子进程；治标：结束父进程，由 init 接管回收 |
| 把"终端关闭 → 服务消失"归因于 SIGTERM | 终端断开时内核发的是 **SIGHUP(1)**；信号记错后也解释不了 `nohup` 为什么有效 | 终端断开时，内核向该终端的前台进程组/会话首进程发 **SIGHUP(1)**，shell 退出时再向自己的作业补发同一信号。`nohup` 把该进程对 **SIGHUP** 的处置设为 `SIG_IGN`（子进程继承），stdin 为终端则重定向到 `/dev/null`，stdout 为终端则重定向到 **`nohup.out`**（此时 stderr 合并进同一文件） |
| 用 `jobs` 取后台服务的 PID | `jobs` 只属于当前 shell；服务脱离终端后 shell 与作业表一并消失，脚本/非交互场景取不到 | `echo $!` 取得最近一个后台进程的 PID，**启动后需立即取** |
| `cat f \| awk ...` | 多一个无用进程 | `awk '...' f` |
| `awk ... \| uniq -c` | 结果错误：`uniq` 只合并**相邻**重复 | 先 `sort` 再 `uniq -c`，或直接用 awk 关联数组 |

## 6. 每日一题（面试自测）

### 6.1 硬链接与软链接

**题目**：`ln a.txt hard.txt`、`ln -s a.txt soft.txt`，然后 `rm a.txt`。`cat hard.txt` 与 `cat soft.txt` 分别什么结果？

**我的原答**：`cat hard.txt` 结果与 `rm a.txt` 前一致；`cat soft.txt` 报错。原理：硬链接本质是为文件背后的 inode 新增一个名字，删去 `a.txt` 不影响；软链接存的是 `a.txt` 的路径，原文件没了自然报错。

**判定：8/10 ✅** —— 机制说对了，补充一个术语：**链接计数**。删除一个名字只是计数 -1，inode 与数据仍在。

### 6.2 `find` 复合条件删除

**题目**：删掉 `/data` 下修改超过 30 天且大于 50MB 的 `.tar.gz`；并说明三种删除方式的区别。

**我的原答**：`find "/data/*.tar.gz" -mtime +30d -size +50m -exec rm -f {} +`；`-exec rm {} \;` 是逐个处理占位符；`-exec rm {} +` 一次性导入、效率更高；`-delete` 记不清，应该也是删除操作。

**判定：4/10 ⚠️** —— 三处错误：路径不应带通配符、`+30d`/`+50m` 不可靠、缺少 `-type f`。`-delete` 不是"快捷写法"，而是内置动作：不 fork、隐含 `-depth`。

| 正确写法 | 命令 |
|---|---|
| 先预览 | `find /data -type f -name '*.tar.gz' -mtime +30 -size +50M -print` |
| 再删除 | `find /data -type f -name '*.tar.gz' -mtime +30 -size +50M -delete` |

### 6.3 `$(ls)` 与引号

**题目**：`for f in $(ls)` 有什么问题？应怎么写？`rm $file` 与 `rm "$file"` 的差别？

**我的原答**：引号部分答对（无引号时含空格或其他分隔符会导致意外，可能某些部分被当作一个命令）；`$(ls)` 的问题回答为"空目录会迭代空内容导致错误"。

**判定：5/10 ⚠️** —— 引号那半正确，但"被当命令"应改为"被当**多个参数**"；`$(ls)` 的问题在于**分词/展开**，与空目录无关（空目录**不报错**，循环体一次都不执行）。

### 6.4 `df` 与 `du` 对不上

**题目**：`df -h` 显示 `/` 满，但 `du -sh /*` 加起来只有一半，可能原因？如何定位？

**我的原答**：不清楚，可能是日志文件占用过高。

**判定：2/10 ❌** —— 方向沾边，标准答案是「**文件已被 `rm`，但进程仍持有 fd**」→ `lsof +L1`。

### 6.5 僵尸进程

**题目**：怎么产生？`ps` 中是什么状态？父进程该做什么？`kill -9` 能解决吗？

**我的原答**：父进程还在而子进程已死；`ps` 的进程状态列显示 `Z`；不占内存与 CPU，但占用 PID；父进程应回收子进程；`kill -9` 解决不了，因为它本身已是死进程。

**判定：8/10 ✅** —— 核心正确。精确表述：**子进程已退出、父进程未 `wait()` 回收**；若父进程先退出，init 会收养，就不会成为僵尸。

### 6.6 awk 按小时统计请求数

**题目**：nginx 日志首字段是 IP、`[$time_local]` 是第 4 字段，统计**每小时**请求数并倒序取前 5。

**我的原答**：`cat /tmp/log/nginx/nginx.log | awk '{}' | uniq -c | tail -5`；想用 `for i in (24)` 循环配合 awk 取第 4 字段再比较。

**判定：2/10 ❌** —— 缺 `sort`（`uniq` 只合并相邻行）；不会取小时字段；思路上用循环是错的，awk 一次遍历即可聚合。

```bash
# $4 = [01/Apr/2025:10:00:00，"小时"是第 4 字段按 : 切开的第 2 段
awk '{split($4,t,":"); c[t[2]]++} END{for(h in c) print c[h], h}' access.log | sort -rn | head -5

# 纯 awk 输出、少一层管道（依赖日志格式：$4=`[01/Apr/2025`、$5=小时）
awk -F'[: ]' '{c[$5]++} END{for(h in c) print c[h], h}' access.log | sort -rn | head -5
```
