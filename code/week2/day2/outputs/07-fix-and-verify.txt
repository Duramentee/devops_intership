## 结论（逐段对应上面的原始输出）

| 段落 | 结论 |
|---|---|
| `### proxy` | shell 中配置了 `http_proxy=http://127.0.0.1:9674` 等四个代理变量，`no_proxy` 中包含 `172.18.*`，因此 curl 对 `172.18.0.2` 的请求按环境变量判断本应当绕过代理。 |
| `### curl-noproxy` | 加上 `--noproxy '*'` 参数之后得到的不是 `502`，而是 `curl: (28) Connection timed out after 10002 milliseconds`，说明从 WSL 发行版到节点容器地址 `172.18.0.2` 的 31873 端口之间不存在可用的转发路径；第一次实验得到的那一条 `502` 结论作废。 |
| `### ip route get 172.18.0.2` | 路由表中存在一条经由 `172.18.128.1` 的条目，但是数据包在超时时间内没有得到任何响应，说明问题不是本机路由缺失，而是该地址无法从 WSL 发行版直接到达。 |
| `### 节点容器内部访问 localhost:31873` | 在节点容器内部执行 `curl http://localhost:31873/` 得到 `HTTP/1.1 200 OK` 与 `<h1>Hello DevOps</h1>`，说明 kube-proxy 确实在节点上写入了节点端口的转发规则，并且规则可以把数据包转发到后端 Pod。 |
| `### 集群内部访问 172.18.0.2:31873` | 从一个临时 busybox Pod 访问节点地址与节点端口同样得到 `<h1>Hello DevOps</h1>`，说明节点端口在集群网络内部可以正常使用。 |
| `### 集群内部访问 ClusterIP 10.96.135.12:8080` | 通过 ClusterIP 访问同样成功，说明 ClusterIP 与 NodePort 两条路径都工作正常。 |
| `### 删除 webapp-nodeport` | 输出为 `service "webapp-nodeport" deleted from default namespace`，删除操作成功。 |
| `### 删除之后查询端点对象` | 输出为 `Error from server (NotFound): endpoints "webapp-nodeport" not found`，说明删除 Service 之后，与它同名的 Endpoints 对象也被删除，笔记 3.4 节阶段六第 24 行的预测成立。 |
| `### webapp 的选择器与端点` | 选择器的取值是 `{"app":"webapp"}`，说明第 8 项任务中修改过的选择器已经改回原值；端点列表是 `10.244.0.2:8080,10.244.0.3:8080`，与当前两个处于就绪状态的 Pod 一致。 |
| `### pod 沙箱与创建时刻` | `r8jvf` 的 uid 是 `3e495f6c…`、创建时刻是 `2026-09-18T06:35:47Z`、重启计数是 2；`qs5xh` 的 uid 是 `8e086c43…`、创建时刻是 `2026-09-19T08:30:16Z`、重启计数是 1。两个 Pod 的 `status.startTime` 与创建时刻取值相同，说明它只在 Pod 开始被 kubelet 接管时写入一次，沙箱重建不会更新它，因此不能用它判断沙箱是否被重建。 |
| `### 节点容器启动时刻` | 取值是 `2026-09-20T01:39:14Z`，也就是北京时间 09:39，说明节点容器在本次实验开始之前被重新启动过。 |
| `### Last State` | 上一个容器终止的原因是 `Unknown`，退出码是 `255`，开始时间是 9 月 19 日 15:31，结束时间是 9 月 20 日 09:39，与节点容器的启动时刻吻合，说明容器是在容器运行时停止时被终止的。 |
| `### Events` | 事件中出现 `SandboxChanged`，原文是 `Pod sandbox changed, it will be killed and re-created.`，这是判断沙箱被重建的权威依据；随后是 `Pulled`、`Created`、`Started` 三条记录。 |
| 容器环境变量 | 两个 Pod 的环境变量中都包含 `WEBAPP_*` 与 `WEBAPP_NODEPORT_*` 两组变量。`r8jvf` 的 Pod 对象创建于 Service 创建之前，却仍然拥有这两组变量，原因是它的容器在 Service 创建之后被重建过，说明 kubelet 是在创建容器时计算并注入这些变量，因此准确的要求是 Service 必须先于容器的创建存在。 |
| 环境变量的时效性 | `WEBAPP_NODEPORT_*` 这一组变量在当前时刻仍然存在，而 `webapp-nodeport` 这个 Service 在三分钟之前已经被删除，说明环境变量是容器创建时刻的快照，创建之后不会再更新。 |
