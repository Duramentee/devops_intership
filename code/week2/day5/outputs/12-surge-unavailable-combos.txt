# 步骤 12：maxSurge 与 maxUnavailable 的取值组合实验
# 记录时刻（UTC）：2026-09-22T07:29:58Z
# 副本数量固定为 2，每种组合都配合一次镜像变更来触发滚动升级，
# 因为只修改策略字段不会创建新的 ReplicaSet，也就不会发生任何 Pod 替换（该结论见 04b-apply-strategy-clean.txt）。

===== 组合一：maxSurge=1 maxUnavailable=0（本条已在步骤 6 的升级窗口中得到）=====
# 依据：07-rs-watch.txt 中 webapp-54c66c8c74 的 DESIRED 由 0 增到 1，webapp-7f78498c55 由 2 减到 1，
# 随后 webapp-54c66c8c74 增到 2、webapp-7f78498c55 减到 0，两个 ReplicaSet 的 DESIRED 之和最大为 3 最小为 2，
# 因此 Pod 总数上限等于 2 加 maxSurge，可用 Pod 数量下限等于 2 减 maxUnavailable（本次为 2）。

===== 组合二：maxSurge=0 maxUnavailable=1，镜像由 webapp:v6 变为 webapp:v7 =====
# 变更之前的镜像：webapp:v6
# 本次使用的清单：/tmp/deploy.combo01.yaml

    # 5. 本次要新增的第三个字段是 spec.strategy.rollingUpdate.maxUnavailable，
    #    取百分数时由控制平面向下取整，并且它与 maxSurge 不允许同时为 0。
          maxSurge: 0
