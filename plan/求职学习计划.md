## 1. 学习主线（一句话）

> 用 Go 写一个小服务 → 打成容器镜像 → 部署到本地 K8s → 接上 GitHub Actions → 让「提交代码」自动变成「新版本上线」。

**这一个项目贯穿全程，学完就是简历项目。** 所有模块都在为它服务，不要另起炉灶。

### 项目分阶段形态（每阶段都能单独演示）

| 阶段 | 项目形态 | 对应时间 | 可演示的内容 |
|---|---|---|---|
| 1 | Go 服务与 Dockerfile | 已完成（第 1 周） | 25.3MB 的非 root 镜像，启动之后可以访问 |
| 2 | 部署到 Kubernetes | 第 2 周 | 用 Deployment、Service、ConfigMap 部署应用，能够扩容、升级、回滚 |
| 3 | 数据持久化与故障排查 | 第 3 周 | 数据在 Pod 重建之后仍然存在；能够用事件与日志定位故障 |
| 4 | CI/CD 流水线 | 第 4 周 | 提交代码之后自动构建镜像，并更新集群中运行的版本 |
| 加分项 | Go 与 client-go 小工具 | 第 4 周之后或面试间隙 | 用 Go 调用 Kubernetes API，例如自动清理处于 Evicted 状态的 Pod |

## 3. 每个主题的标准动作（实践优先）

1. 先动手：直接按当天的任务清单操作，遇到报错再查文档与教材，不要求先把理论读完。
2. 每条命令都要在 `notes/weekN/dayN.md` 中记录原始输出，并在输出旁边写一行结论，说明它证明了什么。
3. 只补系统级机制：即组件之间如何协作、一次操作在系统中如何流转、对象之间是什么关系。实现级细节的处理方式见第 8 节。
4. 每天用「面试问答卡」自查一次：先口头回答，再对照要点检查遗漏，答不出来的内容写进笔记的「我的疑问」部分。
5. 每周六做一次串联演示，并把可以展示的命令与输出写进 `code/weekN/README.md`。

### 方向定位：不是"放弃开发"，是换到云原生开发

| 认知 | 说明 |
|---|---|
| 整个云原生生态是 Go 写的 | K8s、Docker、etcd、Prometheus、Helm、Terraform 全是 Go，「开发能力」在这里直接变现 |
| 你要投的不是"业务开发" | 目标岗位关键词：**云原生开发、平台工程（Platform Engineering）、基础架构、SRE 工具链** |
| DevOps 是入口不是终点 | 先靠 K8s + CI/CD 拿到实习，再往 Controller/Operator/工具链方向转 |
| 差异化武器 | 会用 Kubernetes 的人很多，而能够用 Go 调用 Kubernetes API 做二次开发的人很少，因此 client-go 小工具是投递平台开发方向时的差异化产出 |

### 简历项目怎么写（就用主线项目，数字按实测值填写）

```text
项目名：<你的服务名> 云原生部署与 CI/CD

  并以非 root 用户运行、只保留必要 capability

  然后更新集群中运行的版本，从提交到上线全流程 < x 分钟（实测后填写）
- 使用 Go 与 client-go 编写小工具，自动清理处于 Evicted 状态的 Pod
```

## 8. 深度边界：保留系统级机制，移除实现级细节

判断标准：某个知识点是否影响「理解整个系统如何运转」。影响则保留，不影响则移除。

| 类别 | 内容 | 处理方式 |
|---|---|---|
| 保留 | 一次 `kubectl apply` 之后，从 API Server 到 etcd、控制器、调度器、kubelet、容器运行时的完整流转过程 | 必须能够完整讲出来，是面试中区分「会使用工具」与「理解系统」的关键。 |
| 保留 | 控制器与 kubelet 的职责划分（谁负责维持副本数量、谁负责重启容器） | 需要能够说清两者边界，这也是第 2 周最容易混淆的地方。 |
| 保留 | Service 与 Endpoints 的关系，以及 kube-proxy 在其中的作用 | 需要能够解释为什么 Pod 的 IP 变化之后访问不受影响。 |
| 保留 | 镜像从构建到被节点拉取使用的完整路径 | 需要能够解释为什么必须先执行 `kind load docker-image`。 |
| 移除 | Go 运行时如何注册信号处理器、容器内 PID 1 的信号语义 | 第 1 周已经记录过结论，后续不再展开。 |
| 移除 | capability 位图的位运算、cgroup 参数的细节 | 结论已经在第 1 周的笔记中，不再补充新的实验。 |
| 移除 | 构建缓存 key 的完整计算过程、overlay2 的挂载细节 | 同上。 |
| 移除 | etcd 的存储格式与一致性算法、CNI 与 CSI 插件的内部实现 | 属于实现级细节，入职之后再补。 |

## 9. 面试防露怯机制

担心「面试被问到却完全不知道」是正常的，应对方式不是把内容全部学完，而是把可能被问到的问题提前过一遍。

| 机制 | 具体做法 | 频率 |
|---|---|---|
| 面试问答卡 | 每天的主题都附有四道常见问题与答题要点，先口头回答，再对照要点检查遗漏 | 每天 30 分钟 |
| 模拟面试 | 由我按岗位方向出题，你口头回答，我指出表达与知识上的问题 | 每周一次，从第 2 周开始 |
| 面试复盘 | 每场真实面试之后立即写复盘，记录答不上来的问题 | 每次面试之后 |
| 问答卡汇总 | 把全部问答卡汇总到 `notes/面试问答卡.md`，面试前一天通读 | 面试前一天 |
| 补充清单 | 面试中答不上来的问题进入补充清单，按优先级逐个补齐 | 面试之后 |
