## 1. 学习主线（一句话）

> 用 Go 写一个小服务 → 打成容器镜像 → 部署到本地 K8s → 接上 GitHub Actions → 让「提交代码」自动变成「新版本上线」。

**这一个项目贯穿全程，学完就是简历项目。** 所有模块都在为它服务，不要另起炉灶。

### 项目分阶段形态（每阶段都能单独演示）

| 阶段 | 项目形态 | 用到的知识 |
|---|---|---|
| 1 | Go 服务 + Dockerfile，`docker run` 能跑 | 模块 01 |
| 2 | 手写 Pod / Deployment / Service YAML | 模块 02、03 |
| 3 | 配置外置（ConfigMap/Secret）+ PVC 持久化 | 模块 03、04 |
| 4 | 滚动升级 / 回滚 + 资源限制 | 模块 05、07 |
| 5 | GitHub Actions：lint → test → build 镜像 | Actions Session 1-4、8 |
| 6 | 提交镜像 + 自动部署到本地 K8s | Actions Session 9-12、Lab 1-8 |
| 7 | HPA 压测 + 探针 + 看日志排障 | 模块 04、07、08 |
| 8 | 【云原生开发加分项】用 Go + `client-go` 写一个 K8s 小工具（如自动清理 Evicted Pod），或一个 CRD + Controller | 模块 08 + K8s API |

## 3. 每个主题的标准动作（照做，别跳过）

1. 读对应 `docs/k8s_in_action/0X-*.md`（已有提炼，不要重读原书）。
2. 打开 `assets/text/k8s-in-action.txt` 只读命中处前后 30 行（`grep -n` 拿行号）补细节。
3. **动手实践**小节照做一遍，报错就记进「易错点」。
4. 做「自测题」，让 AI 批改。
5. 结论写进 `notes/weekN/dayN.md` 四段：概念 / 命令 / 易错点 / 我的疑问。

### 方向定位：不是"放弃开发"，是换到云原生开发

| 认知 | 说明 |
|---|---|
| 整个云原生生态是 Go 写的 | K8s、Docker、etcd、Prometheus、Helm、Terraform 全是 Go，「开发能力」在这里直接变现 |
| 你要投的不是"业务开发" | 目标岗位关键词：**云原生开发、平台工程（Platform Engineering）、基础架构、SRE 工具链** |
| DevOps 是入口不是终点 | 先靠 K8s + CI/CD 拿到实习，再往 Controller/Operator/工具链方向转 |
| 差异化武器 | 会用 K8s 的人多，**能用 Go 写 Controller / kubectl 插件的人少** → 第 6 周的小工具就是你的差异化 |

### 简历项目怎么写（就用主线项目）

```text
项目名：<你的服务名> 云原生部署与 CI/CD
- 用 Go 编写后端服务，多阶段构建把镜像体积从 xxx MB 压到 xx MB
- 使用 Deployment + Service + ConfigMap + PVC 部署到 Kubernetes，
  编写存活/就绪探针实现故障自愈与零中断滚动升级
- 用 GitHub Actions 搭建 CI/CD：PR 触发 lint/test，main 分支自动构建镜像并部署，
  从提交到上线全流程 < x 分钟
- 配置 requests/limits 与 HPA，压测下自动从 1 副本扩到 5 副本
```

数字要真实，跑出来再填。

### 高频面试题范围（第 8 周集中刷）

| 方向 | 典型题 |
|---|---|
| Linux | 负载高怎么查、僵尸进程、软硬链接区别 |
| 网络 | TCP 三次握手、TIME_WAIT、DNS 解析过程 |
| Docker | 镜像分层、多阶段构建、容器 vs 虚拟机 |
| K8s | Pod 生命周期、Deployment 升级流程、Service 类型区别、探针区别、QoS |
| CI/CD | build once 原则、secrets 管理、OIDC 为什么比长期密钥好 |
| 排障 | Pod 起不来怎么查（`describe`→`logs`→`events`） |
