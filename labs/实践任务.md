## 第一部分：基础命令与系统信息（理论 + 实操）

### 任务 1：查看系统基本信息

**要求：**  
执行以下命令，并记录输出结果，然后回答理论问题。

```bash
uname -a
cat /etc/os-release
hostname
uptime
whoami
id
```

**理论问题：**  
1. `uname -a` 输出中的内核版本、主机名、架构分别是什么？
2. `uptime` 输出的三个负载值（load average）是什么意思？如何判断系统负载是否过高？

---

> **参考答案与命令详解**

**uname -a 实测输出：**
```
Linux MaybeUnix 6.6.87.2-microsoft-standard-WSL2 #1 SMP PREEMPT_DYNAMIC Thu Jun  5 18:30:46 UTC 2025 x86_64 GNU/Linux
```

| 字段 | 值 | 含义 |
|------|-----|------|
| 1 | `Linux` | 内核名称（OS name） |
| 2 | `MaybeUnix` | **主机名**（hostname） |
| 3 | `6.6.87.2-microsoft-standard-WSL2` | **内核版本**（kernel release，微软定制，说明是 WSL2 内核） |
| 4 | `#1 SMP PREEMPT_DYNAMIC ... 2025` | 内核构建信息（编译号 / 多核 SMP / 抢占模式 / 编译时间） |
| 5 | `x86_64` | **架构**（machine architecture） |
| 6 | `GNU/Linux` | 操作系统名称 |

> **理论题①答案**：内核版本 `6.6.87.2-microsoft-standard-WSL2`、主机名 `MaybeUnix`、架构 `x86_64`。

**uptime 实测输出：**
```
 10:09:23 up 46 min,  0 users,  load average: 0.66, 1.14, 1.04
```

| 部分 | 值 | 含义 |
|------|-----|------|
| `10:09:23` | 当前系统时间 | 当前时刻 |
| `up 46 min` | 运行时长 | 已开机运行 46 分钟 |
| `0 users` | 登录用户数 | 当前登录终端用户数 |
| `load average` | `0.66, 1.14, 1.04` | 过去 **1 分钟 / 5 分钟 / 15 分钟**的平均负载 |

> **理论题②答案**：
> - **含义**：load average 是「一段时间内处于可运行态（R）或不可中断睡眠态（D，如等磁盘 I/O）的进程平均数量」的滑动平均值。三个数分别反映 1、5、15 分钟的趋势——1 分钟值 > 15 分钟值说明负载在**上升**，反之下降。
> - **判断依据（经验法则）**：与 **CPU 核心数**（`nproc`）对比。本机 16 核，负载 0.66 远低于 16 → 系统空闲；若负载**持续大于核心数**（如 16 核机器 load > 16）说明进程排队、CPU/I/O 过载。
> - **注意**：负载高不一定是 CPU 忙——D 状态（磁盘 I/O）也计入，需用 `top`/`iostat` 区分瓶颈。

### 任务 2：磁盘与内存检查

**要求：**  
使用命令查看磁盘使用率、内存使用率、CPU 信息。

```bash
df -h
free -h
nproc
lscpu | head
lsof -i :8080
```

**实操练习：**  
- 找出根分区 `/` 的使用率，如果超过 80%，你会如何排查？列出可能的原因和排查命令。
- 查看当前系统 swap 使用情况，解释 swap 的作用。

---

> **参考答案与命令详解**

**`df -h` 实测（WSL2，根分区挂 `/dev/sdd` 虚拟盘，使用率仅 2%）：**
```
/dev/sdd  1007G  14G  942G   2%  /
```
其余多为 WSL 虚拟文件系统与 Windows 盘（`/mnt/d` 81% 等）。

> **实操①答案（若根分区超 80% 排查思路）：**

| 可能原因 | 排查命令 |
|---------|---------|
| 日志膨胀（`/var/log`、journald） | `du -sh /var/log/*`；`journalctl --disk-usage` |
| 大文件（core dump、备份、下载残留） | `find / -xdev -type f -size +1G -exec ls -lh {} +` |
| 包管理器缓存 | `du -sh /var/cache/apt`；`apt clean` / `dnf clean all` |
| Docker 镜像/容器/卷占空间 | `docker system df` |
| 临时目录 `/tmp`、用户缓存 | `du -sh /tmp ~/.cache` |
| inode 耗尽（小文件太多） | `df -i /` |
| 文件被删除但仍被进程占用 | `lsof +L1` |

通用定位法：从根目录逐层 `du -h -x --max-depth=1 / | sort -h` 找最占空间目录，再深入。

**`free -h` 实测：**
```
               total   used   free   shared  buff/cache  available
Mem:            11Gi  3.7Gi  4.0Gi    68Mi      4.1Gi     7.8Gi
Swap:          3.0Gi  268Ki  3.0Gi
```
- 判断内存压力看 **`available`**（7.8Gi）而非 `used`，因为 `buff/cache`（4.1Gi）可回收。
- **CPU**：`nproc` = 16（8 核 16 线程 i7-12650H），WSL2 虚拟机（`lscpu` 见 `Hypervisor vendor: Microsoft`）。

> **实操②答案（swap）**：当前 swap 总 3.0Gi、used 268Ki（几乎未用 → 内存充足）。
> **swap 作用**：磁盘上的"虚拟内存"区。物理内存不足时内核把**不常用**页面换出到 swap，避免 OOM；但若持续 swap 会导致磁盘 I/O 频繁（thrashing），系统明显变卡。
> 查看命令：`swapon -s` / `cat /proc/swaps`；关停 `swapoff -a`。

**相关命令详解：**

| 命令 | 含义 | 常用 |
|------|------|------|
| `df` | disk free，看**文件系统**容量/使用率（按挂载点） | `-h` 人类单位、`-T` 显示类型、`-i` 看 inode |
| `du` | disk usage，统计**目录/文件**实际占用 | `-s` 只给总计、`-h`、`--max-depth=N` |
| `free` | 查看内存与 swap | `-h` |
| `lsof` | list open files，进程打开的文件/端口 | `-i :8080` 查端口、`+L1` 查已删占用、`-u 用户` |
| `swapon` / `swapoff` | 查看 / 启用 / 关闭 swap | `swapon -s`（等价 `cat /proc/swaps`）；`swapoff -a` |

**`lsof` 输出关键列：**

| 列 | 含义 | 常见值 |
|----|------|--------|
| `FD` | 文件描述符 | `cwd` 工作目录、`txt` 程序本体、`mem` 内存映射、数字 `r`/`w` 读写 |
| `TYPE` | 文件类型 | `REG` 普通文件、`DIR` 目录、`IPv4`/`TCP` 网络 |
| `NAME` | 路径或地址 | 如 `/usr/bin/zsh`、`localhost:8080` |

### 任务 3：创建项目目录结构

**要求：**  
在 `/home/你的用户名/` 下创建以下目录结构：

```
devops-practice/
├── app
├── logs
├── scripts
├── backup
└── config
```

使用一条命令完成创建（提示：`mkdir -p`）。

**理论问题：**  
- 解释 `mkdir -p` 中 `-p` 参数的作用。
- 如何查看一个目录的详细权限？`ls -ld` 和 `ls -l` 有什么区别？

---

> **参考答案与命令详解**

**一条命令建出全部目录：**
```bash
mkdir -p /home/drow/devops-practice/{app,logs,scripts,backup,config}
```
（`{a,b,c}` 是 shell 花括号展开，等价 `mkdir -p a b c` 写 5 个参数。）

> **理论题①答案**：`-p` = parents——父目录不存在时**自动逐层创建**，已存在也不报错（脚本里常用于"确保目录存在"）。

**`mkdir` 常用参数：**

| 参数 | 作用 |
|------|------|
| `-p` | 父目录不存在时自动逐层创建；已存在不报错 |
| `-v` | 显示创建过程 |
| `-m 权限` | 创建时直接指定权限（如 `mkdir -m 700 secret`） |
| `{a,b,c}` | shell 花括号展开，一条命令建多个目录 |

> **理论题②答案**：
> - `ls -l 目录`：列出**目录里的内容**。
> - `ls -ld 目录`：只看**目录自身**的属性（权限/属主），`-d` 表示不进入目录。判断某目录本身权限必须用 `ls -ld`。

**`ls -l` 输出逐字段解读：**
```
-rw-r--r--  2  drow  drow  0  Sep  7 16:39  f1.txt
└──┬───┘  │  │    │     │   │     │      └─ 文件名
   权限   │  │    │     │   │     └─ 修改时间
          │  │    │     │   └─ 文件大小(字节)
   链接数 │  属主  属组
   (硬链接计数)
```
- 首字符文件类型：`-` 普通、`d` 目录、`l` 软链接、`c`/`b` 设备。
- `f2_soft -> f2.txt` 表示软链接及指向；`f1.txt` 与 `f1_hard.txt` 链接数均为 2（同一 inode 两个名字，呼应任务 6 硬链接）。
- `total N`：本目录所有项占用的块总数。

**`ls` 常用参数：**

| 参数 | 作用 |
|------|------|
| `-l` | 长格式（权限/属主/大小/时间） |
| `-a` | 显示隐藏文件（`.` 开头） |
| `-d` | 只列目录本身，不进入其中 |
| `-h` | 大小带单位（常 `-lh` 连用） |
| `-t` / `-r` / `-S` | 按时间 / 倒序 / 按大小排序 |
| `-R` | 递归列出子目录 |

### 任务 4：文件查找与内容查看

**要求：**  
1. 在 `/var/log` 目录下查找所有 `.log` 文件，并统计数量。  
2. 在 `/etc` 目录下查找名字中包含 `ssh` 的文件或目录（不区分大小写）。  
3. 查看 `/etc/passwd` 文件中包含你用户名的行。

**实操练习：**  
- 用 `find` 找出 `/var/log` 下最近 7 天内修改过的 `.log` 文件。
- 用 `grep` 统计 `/etc/passwd` 中有多少个用户使用了 `/bin/bash` 作为登录 shell。

**涉及命令：**  
`find`、`grep`、`wc`、`cat`、`less`、`tail`

---

> **参考答案与命令详解**

**① 找 `.log` 并计数：**
```bash
find /var/log -name '*.log' 2>/dev/null | wc -l    # 实测 = 6
```
`2>/dev/null` 丢弃无权限目录的报错。

**② `/etc` 下含 ssh（不区分大小写）：**
```bash
find /etc -iname '*ssh*' 2>/dev/null    # -iname = 忽略大小写
```

**③ 查看自己用户名所在行：**
```bash
grep -n drow /etc/passwd
# 22:drow:x:1000:1000::/home/drow:/usr/bin/zsh
```
`:` 分隔字段：用户名 / x / UID=1000 / GID=1000 / 注释 / 家目录 `/home/drow` / 登录 shell `/usr/bin/zsh`。

> **实操 A 答案**：`find /var/log -name '*.log' -mtime -7 2>/dev/null`
> 实测为空——说明这些日志 7 天内未改写，属正常。`-mtime -7` 表示"修改时间在 7×24 小时以内"。

> **实操 B 答案**：`grep -c '/bin/bash' /etc/passwd` → 实测 = **1**（仅 root）。因本机 `drow` 的 shell 是 `/usr/bin/zsh`。

### `find` 指令详解

**最常用格式**：`find <路径> [条件] [动作]`

| 类别 | 例子 | 含义 |
|------|------|------|
| 名字 | `-name '*.log'` / `-iname '*ssh*'` | 按文件名（`*` 通配符）；`i` 忽略大小写 |
| 类型 | `-type f`（文件）/`d`（目录）/`l`（链接） | 只找某类 |
| 时间 | `-mtime -7` / `+7` | 7 天内改过 / 超 7 天没改（`-atime` 访问、`-ctime` 状态） |
| 大小 | `-size +100M` / `-1G` | 大于 / 小于某体积 |
| 用户 | `-user drow` | 属主 |
| 组合 | `! -name 'x'`、`-o`（或） | 逻辑 |
| 动作 | `-exec ... {} \;`、`-delete` | 对结果执行命令 / 删除 |
| 限制 | `-maxdepth 2`、`-xdev` | 深度 / 不跨文件系统（防扫进 /mnt/c） |

### `wc` 指令详解

**wc = word count，统计行 / 单词 / 字节数。**

| 参数 | 含义 |
|------|------|
| `-l` | 只数行数（最常用，配合管道计数） |
| `-w` | 只数单词数 |
| `-c` | 只数字节数 |
| `-m` | 字符数 |

> 细节：`wc -l < file` 只输出数字（去掉文件名），`wc -l file` 会带文件名。管道计数用 `命令 | wc -l`。
> 核心套路：**find 找文件 → grep 按内容筛 → wc -l 数行数**。

### `cat` 指令详解（查看/拼接文件）

**作用**：把文件内容整体输出到屏幕（concatenate），适合**小文件**。大文件会刷屏，应改用 `less`。

| 参数 | 作用 |
|------|------|
| `-n` | 输出带行号 |
| `-A` | 显示所有不可见字符（如行尾 `$`、Tab 显示 `^I`） |
| `-b` | 只给非空行编号 |
| `-s` | 压缩连续空行为一行 |

```bash
cat /etc/passwd            # 查看整个文件
cat -n file                # 带行号查看
cat a.txt b.txt > c.txt    # 拼接多个文件到新文件
cat > new.txt              # 用 Ctrl+D 结束，直接敲内容创建文件
```

> **常见误区**：`cat file | grep xx` 多余——grep 直接接文件名即可：`grep xx file`。`cat` 主要用于小文件浏览与拼接。

### `less` 指令详解（分页浏览大文件）

**作用**：**分页查看**大文件/命令长输出，可上下翻页、搜索。`less` 比老命令 `more` 更强（可**向上翻**、可搜索），日常用 less 即可。

```bash
less /var/log/syslog       # 浏览大日志
ps aux | less              # 长输出分页看（管道用法）
```

| 按键/操作 | 作用 |
|-----------|------|
| `空格` / `f` | 向下翻一页 |
| `b` | 向上翻一页 |
| `j` / `k`（或方向键） | 向下 / 向上滚一行 |
| `/关键字` | 向下搜索，`n` 下一个、`N` 上一个 |
| `?关键字` | 向上搜索 |
| `G` / `g` | 跳到文件末尾 / 开头 |
| `q` | 退出 |

> **head/tail 管道的替代**：先 `head`/`tail`/`grep` 缩小范围，再 `| less` 分页浏览是常用组合。

### `head` 指令详解（看开头）

**作用**：只看文件**开头 N 行**（默认 10 行），常用于快速预览文件内容/结构。

| 参数 | 作用 | 示例 |
|------|------|------|
| `-n N` | 显示前 N 行 | `head -n 20 file` |
| `-c N` | 显示前 N 字节 | `head -c 100 file` |
| `-q` | 多文件时不打印文件名标题 | `head -q f1 f2` |

```bash
head /var/log/syslog            # 前 10 行
head -n 5 access.log            # 前 5 行（等价 head -5）
df -h | head                    # 只看磁盘输出前几行
lscpu | head -n 15              # lscpu 输出太长时截取（任务2用过）
```

### `tail` 指令详解（看结尾，日志排查神器）

**作用**：只看文件**末尾 N 行**（默认 10 行）。**`tail -f` 实时跟踪**文件新增内容，是排查日志的第一利器。

| 参数 | 作用 | 示例 |
|------|------|------|
| `-n N` | 显示末尾 N 行 | `tail -n 20 file`（等价 `tail -20`） |
| `-f` | **实时跟踪**文件增长（follow），Ctrl+C 退出 | `tail -f /var/log/syslog` |
| `-F` | 跟踪且**文件被轮转/重建后自动重连**（更稳） | `tail -F /var/log/app.log` |
| `-c N` | 显示末尾 N 字节 | `tail -c 512 file` |

```bash
tail -n 30 /var/log/syslog     # 最近 30 行日志
tail -f /var/log/nginx/access.log   # 实时看访问日志（配合 grep 过滤更高效）
tail -f access.log | grep ' 500 '   # 实时只看 5xx 错误
```

> **实战组合**：排错时开一个 `tail -f` 窗口盯着日志，另开终端操作服务，能立刻看到报错。
> 对比记忆：**head 看头、tail 看尾、less 分页翻、cat 全量输出**；看日志结尾且要动态刷新用 `tail -f`。

## 第三部分：用户、权限与文件属性

### 任务 5：创建用户并分配权限

**要求：**  
1. 创建一个新用户 `devops_test`，并设置密码。  
2. 将用户 `devops_test` 加入 `sudo` 组（或 `wheel` 组，视发行版而定）。  
3. 在 `/home/devops_test` 下创建一个文件 `test.txt`，内容为 `hello devops`。  
4. 修改该文件属主为 `devops_test`，属组为 `devops_test`，权限为 `640`。

**理论问题：**  
- 解释 `640` 权限的含义：属主、属组、其他人的权限分别是什么？
- 什么是 SUID、SGID、Sticky Bit？分别举一个使用场景。

---

> **参考答案与命令详解**

**完整解法：**
```bash
# 1. 创建用户（-m 建家目录，-s 指定登录 shell），再交互式设密码
sudo useradd -m -s /bin/bash devops_test
sudo passwd devops_test

# 2. 加入 sudo 组（Debian 用 sudo 组；CentOS/RHEL 用 wheel 组）
sudo usermod -aG sudo devops_test

# 3. 家目录下创建文件（sudo tee 解决重定向权限问题）
echo "hello devops" | sudo tee /home/devops_test/test.txt

# 4. 改属主:属组 + 权限 640
sudo chown devops_test:devops_test /home/devops_test/test.txt
sudo chmod 640 /home/devops_test/test.txt
```
**验收：** `id devops_test`（存在）、`groups devops_test`（含 sudo）、`cat /home/devops_test/test.txt`、`ls -l` 显示 `-rw-r----- devops_test devops_test`。

> **理论题①答案：`640` 含义**——三个八进制位分别表示 **属主 / 属组 / 其他**，每位的值 = 读(4)+写(2)+执行(1)：

| 位 | 八进制 | rwx | 权限 |
|----|--------|-----|------|
| 属主 user | 6 | `rw-` | 读+写，不可执行 |
| 属组 group | 4 | `r--` | 只读 |
| 其他 other | 0 | `---` | 无权限 |

完整形态 `-rw-r-----`。常见值：`644` 普通文件、`755` 可执行/目录、`600` 私钥、`640` 组内协作组外保密。

> **理论题②答案：SUID / SGID / Sticky Bit（特殊权限位）**

| 特殊位 | 数值 | 作用 | 经典例子 |
|--------|------|------|----------|
| SUID | `4xxx` | 执行时临时以**文件属主**身份运行 | `/usr/bin/passwd`（普通用户借此写 `/etc/shadow`），`ls -l` 属主位显示 `s` |
| SGID | `2xxx` | 文件：以属组身份执行；目录：新建文件自动继承目录属组 | 团队共享目录 `chmod g+s 目录`，属组位显示 `s` |
| Sticky Bit | `1xxx` | 目录内只有文件属主/root 能删除自己的文件 | `/tmp`（`drwxrwxrwt`，other 位显示 `t`） |

设置：`chmod u+s 文件` / `chmod g+s 目录` / `chmod o+t 目录`（数字法 `4755`/`2775`/`1777`）。`ls` 中小写 `s`/`t` = 特殊位且有执行权；大写 `S`/`T` = 特殊位但无执行权。

**相关命令详解：**

| 命令 | 作用 | 常用参数 / 示例 | 说明 / 易错点 |
|------|------|-----------------|---------------|
| `sudo` | 以 root 权限执行 | `sudo 命令`；`sudo -i` 切入 root shell；`sudo -u 用户 命令`；`sudo -l` | 需属于 `sudo` 组（Debian）/`wheel`（CentOS） |
| `useradd` | 创建用户 | `-m` 建家目录；`-s /bin/bash` 指定 shell；`-G 组` 加附加组；`-u UID` | 只建账号**不设密码**；删除用 `userdel -r 用户` |
| `passwd` | 设置/修改密码 | `passwd`（自己）；`sudo passwd 用户`；`-l`/`-u` 加锁/解锁 | 交互式输入，不能明文传参 |
| `usermod` | 修改用户属性 | `-aG 组` 追加到组；`-s shell`；`-l 新名` 改名 | ⚠️ `-aG` 必须带 `-a`（append），否则覆盖原附加组 |
| `echo` / `tee` | 写文件 | `echo x > 文件`；`echo x \| sudo tee 文件` | `sudo echo x > 受限文件` **会失效**（`>` 由普通 shell 先执行） |
| `chown` | 改属主/属组 | `chown 属主 文件`；`chown 属主:属组 文件`；`chown -R 目录` | 冒号同时改两者；`:属组` 只改组 |
| `chmod` | 改权限 | 数字 `chmod 640`；符号 `chmod u+x`/`g-w` | 数字法 r=4,w=2,x=1；符号法 u/g/o/a + -/+/= |
| `id` / `groups` / `whoami` | 查看身份 | `id 用户`；`groups`；`whoami` | `id` 看 uid/gid 及全部组，可验证加组是否成功 |

### 任务 6：软链接与硬链接

**要求：**  
1. 在 `/tmp` 下创建一个文件 `original.txt`，写入任意内容。  
2. 创建该文件的硬链接 `hard.txt` 和软链接 `soft.txt`。  
3. 删除原文件后，观察两个链接的变化。

**理论问题：**  
- 为什么删除原文件后，硬链接仍然能访问内容，而软链接失效？
- 硬链接和软链接在 inode 层面的区别是什么？

---

> **参考答案与命令详解**

**完整解法：**
```bash
# 1. 创建原文件
echo "原始内容" > /tmp/original.txt

# 2. 创建链接：ln 默认硬链接；-s 表示软链接（symbolic）
ln /tmp/original.txt /tmp/hard.txt     # 硬链接 hard.txt
ln -s /tmp/original.txt /tmp/soft.txt  # 软链接 soft.txt

# 3. 用 ls -li 查看 inode（-i 显示 inode 号）与链接数
ls -li /tmp/original.txt /tmp/hard.txt /tmp/soft.txt
# 期待：original.txt 与 hard.txt 的 inode 号相同、链接数=2；soft.txt 是独立 inode、显示 -> original.txt

# 4. 删除原文件，再访问两个链接
rm /tmp/original.txt
cat /tmp/hard.txt    # ✅ 仍能读到 "原始内容"
cat /tmp/soft.txt    # ❌ No such file or directory（指向的路径已不存在）
```

**观察结论：**
- 删除原文件后：**硬链接仍可访问内容，软链接失效**。
- `hard.txt` 与 `original.txt` 指向同一 inode，`rm` 只是减少一次目录引用计数（link count 2→1），只要还有一个名字指向 inode，数据就不释放。
- `soft.txt` 存的是"目标路径字符串"，删除目标文件后它指向的路径已不存在，因此打开失败（`ls -l` 会显示红/断链 `-> original.txt`）。

**理论题① 答案：** 硬链接与目标共享 inode，删除原文件名只是让 inode 引用计数减一，数据仍在（硬链接仍有效）；软链接保存的是路径，删掉目标后路径失效，故打不开。

**理论题② 答案（inode 层面区别）：**

| 对比项 | 硬链接 | 软链接（符号链接） |
|--------|--------|--------------------|
| inode | 与目标**共用同一个 inode** | 独立的新 inode（文件类型为 `l`） |
| 存储内容 | 与目标同一份数据块 | 存的是**目标路径字符串** |
| 文件大小 | 与目标相同 | 等于路径长度（很小） |
| `ls -l` 显示 | 普通文件，链接数列为 2 | `lrwxrwxrwx`，指向 `-> 目标` |
| 跨文件系统 | ❌ 不可以 | ✅ 可以 |
| 指向目录 | ❌ 不可以 | ✅ 可以 |
| 删除原文件 | 仍可通过链接访问 | 链接失效（断链） |
| 创建命令 | `ln 目标 链接名` | `ln -s 目标 链接名` |

**`ln` 指令详解（链接相关命令）：**

| 命令 | 作用 | 常用参数 |
|------|------|----------|
| `ln 目标 链接名` | 创建**硬链接** | `-i` 覆盖前询问 |
| `ln -s 目标 链接名` | 创建**软链接** | `-s` symbolic；`-f` 强制覆盖已存在链接；`-n` 把指向目录的链接当普通文件 |
| `ls -li` | 查看文件 **inode 号**与链接数 | `-i` 显示 inode；`-l` 第二列即硬链接数 |
| `readlink 链接` | 查看软链接指向的真实路径 | — |
| `stat 文件` | 查看 inode / 链接数 / 类型等详细信息 | — |

> **记忆要点**：硬链接 = 给同一 inode **再加一个名字**（引用计数 +1）；软链接 = **一个指向路径的小文件**（类似 Windows 快捷方式）。`rm` 硬链接只减引用计数，删软链接只删那个小文件，都不动目标本身。

## 第四部分：文本处理与日志分析

### 任务 7：分析 Nginx/Apache 风格日志

**背景：**  
假设你有一条模拟的 Web 访问日志，内容如下（保存为 `access.log`）：

```
192.168.1.10 - - [01/Apr/2025:10:00:00 +0800] "GET /index.html HTTP/1.1" 200 1024
192.168.1.11 - - [01/Apr/2025:10:01:00 +0800] "POST /api/login HTTP/1.1" 401 512
192.168.1.12 - - [01/Apr/2025:10:02:00 +0800] "GET /images/logo.png HTTP/1.1" 304 0
192.168.1.10 - - [01/Apr/2025:10:03:00 +0800] "GET /about HTTP/1.1" 200 2048
192.168.1.13 - - [01/Apr/2025:10:04:00 +0800] "GET /api/data HTTP/1.1" 500 256
192.168.1.11 - - [01/Apr/2025:10:05:00 +0800] "GET /index.html HTTP/1.1" 200 1024
```

**要求：**  
1. 统计日志总行数。  
2. 统计访问最多的 IP 地址。  
3. 统计状态码为 `200` 的请求数量。  
4. 找出状态码为 `500` 的请求对应的 IP 和请求路径。  
5. 将所有请求路径去重后输出。

**涉及命令：**  
`wc`、`awk`、`sort`、`uniq`、`grep`、`cut`

**实操提示：**  
- 先用 `awk '{print $1}'` 提取 IP，再排序统计。
- 状态码在字段 `$9` 位置（根据实际日志格式调整）。

---

> **参考答案与命令详解**

**完整答案：**
```bash
# ① 总行数
wc -l access.log                                        # → 6

# ② 访问最多的 IP（排序取第一）
awk '{print $1}' access.log | sort | uniq -c | sort -rn | head -1
#     192.168.1.10 2   (与 192.168.1.11 并列 2)

# ③ 状态码 200 数量
grep -c ' 200 ' access.log                              # → 3

# ④ 状态码 500 的 IP 和路径
awk '$9==500 {print $1, $7}' access.log                 # → 192.168.1.13 /api/data

# ⑤ 请求路径去重
awk '{print $7}' access.log | sort -u
#   /about /api/data /api/login /images/logo.png /index.html
```

**管道统计标配**：`sort | uniq -c | sort -rn`（先排序再去重计数再按次数倒序）；`sort -u` 直接去重。

### grep / sed / awk 详解（文本处理三剑客）

| 工具 | 定位 | 干的事 |
|------|------|--------|
| `grep` | 行**筛选** | 只保留/删除包含某模式的行 |
| `sed` | 行**编辑** | 对行做替换、删除、打印（流编辑器） |
| `awk` | 行**结构化处理** | 按字段拆分做统计、格式化输出、计算 |

> 记忆口诀：**grep 挑行，sed 改行，awk 算列**。

#### `grep` —— 按模式过滤行

**语法**：`grep [选项] 模式 文件`

```bash
grep ' 200 ' access.log        # 状态码 200 的行（注意两边空格防误匹配）
grep -c ' 200 ' access.log     # 计数 → 3
```

**核心选项：**

| 选项 | 含义 | 记忆 |
|------|------|------|
| `-i` | 忽略大小写 | ignore case |
| `-c` | 只数匹配行数 | count |
| `-v` | 反选（不匹配的行） | invert |
| `-n` | 显示行号 | number |
| `-E` | 扩展正则（`\|` 替代、`+`、`()`） | extended |
| `-r`/`-R` | 递归搜目录 | recursive |
| `-l` | 只列文件名 | files with match |
| `-A2`/`-B2` | 匹配行后/前各 2 行 | after/before |

```bash
# 匹配 500 或 401
grep -E ' (500|401) ' access.log
# 日志看错误（所有 4xx/5xx）
grep -E ' (4[0-9]{2}|5[0-9]{2}) ' access.log
```

#### `sed` —— 流式编辑（替换/删除/打印）

**语法**：`sed [选项] '定位+动作' 文件`

| 场景 | 命令 | 说明 |
|------|------|------|
| 打印第 3 行 | `sed -n '3p' access.log` | `-n` 静默 + `p` 打印 |
| 只替换不改文件 | `sed 's/GET/FETCH/' access.log` | `s/旧/新/` 默认只替换每行第一个，输出到屏幕 |
| 替换全部 | `sed 's/GET/FETCH/g' file` | 加 `g` 全行替换 |
| 原地改文件 | `sed -i 's/GET/FETCH/' file` | `-i` 直接写回 |
| 原地改并留备份 | `sed -i.bak 's/x/y/' file` | 生成 `file.bak` |
| 删行 | `sed '/^#/d' /etc/ssh/ssh_config` | `d` 删注释行 |
| 打印 2–4 行 | `sed -n '2,4p' file` | 行区间 |

> `sed`/`grep` 默认**不改源文件**（输出到 stdout），落盘需加 `-i`。`s///` 结构 = `s/正则/替换文本/标志`，标志常用 `g`（全部）、数字（第几个）、`p`、`i`（忽略大小写）。

#### `awk` —— 按列统计/格式化（三剑客中最强，一门小型语言）

awk 不止是命令，而是一套**完整的文本处理语言**：自动按分隔符把每行拆成字段，然后支持变量、数组、正则、流程控制、内置函数与格式化输出。擅长"按列计算与统计"。

**awk 程序的基本结构：**

```
awk [选项] '模式 {动作} 模式 {动作} ...' 文件
```

- **模式（pattern）**：决定哪些行执行动作。可省略（= 所有行）、或用条件/正则/`BEGIN`/`END`。
- **动作（action）**：用 `{}` 包裹，对命中的行执行。可省略（= 默认打印整行 `print $0`）。
- 逐行读取 → 判断模式 → 执行动作，循环往复直到文件结束。

**执行流程三阶段：**

| 阶段 | 写法 | 执行时机 |
|------|------|----------|
| 开头 | `BEGIN { ... }` | **读文件前**执行一次（常用于打印表头、初始化变量、设分隔符） |
| 主体 | `模式 { 动作 }` | 对每一行执行 |
| 结尾 | `END { ... }` | **所有行处理完后**执行一次（常用于汇总统计、打印结果） |

---

##### 命令行选项（flag）

| 选项 | 作用 | 示例 |
|------|------|------|
| `-F 分隔符` | 指定**输入字段分隔符**（等价设置变量 `FS`） | `awk -F: '{print $1}' /etc/passwd`（按冒号切） |
| `-v 变量=值` | 在执行前给变量赋值（可多次） | `awk -v t=200 '$9==t' access.log` |
| `-f 程序文件` | 从文件读取 awk 程序（程序较长时用） | `awk -f myprog.awk data.txt` |
| `-e 程序` | 直接执行一段程序（与 `-f` 可混用） | `awk -e '{print $1}'` |
| `-F` 正则字符类 | 分隔符可传正则 | `awk -F'[ :]' '{...}'`（按空格或冒号切） |

> 也支持长选项 `--field-separator`、`--assign`；多数发行版默认是 gawk（GNU awk），可用 `awk --version` 确认。

**字段分隔符专项：** `-F` 与变量 `FS` 等价；输出分隔符是 `OFS`。

| 写法 | 效果 |
|------|------|
| `awk -F: '{print $1}' /etc/passwd` | 按 `:` 拆分（处理 passwd、csv 常用） |
| `awk -F' +' '{print $2}' file` | 按 1 个以上空格切（正则） |
| `awk -F'[ ,]' '{print $2}' file` | 按空格或逗号切 |
| `-v FS=: -v OFS=, '{print $1,$3}'` | 读用冒号、输出用逗号 |

---

##### 内置变量（重点）

| 变量 | 含义 | 说明 |
|------|------|------|
| `$0` | 整行内容 | 打印整行 |
| `$1` `$2` … | 第 1、2… 个字段 | 字段从 1 开始编号 |
| `NF` | 当前行**字段总数** | `$NF` = 最后一个字段（最常用） |
| `NR` | **累计**处理的行号 | 多个文件时继续累加，不归零 |
| `FNR` | 当前文件内的行号 | 每个文件都从 1 开始 |
| `FS` | 输入字段分隔符 | 默认空格/制表符 |
| `OFS` | 输出字段分隔符 | `print $1,$2` 时字段间插入的字符，默认空格 |
| `RS` | 输入记录（行）分隔符 | 默认换行 `\n` |
| `ORS` | 输出记录分隔符 | 默认换行 |
| `FILENAME` | 当前处理文件名 | 从 stdin 读时为 `-` |
| `ARGC` / `ARGV` | 命令行参数个数 / 参数数组 | `ARGV[1]` 是第一个文件 |
| `SUBSEP` | 多维数组下标分隔符 | 默认 `\034`，一般用不到 |
| `OFMT` | 数字的默认打印格式 | 默认 `%.6g` |

> **NR vs FNR 区别**：处理多个文件时，`NR` 是所有文件累加的总行号，`FNR` 是"当前这个文件里的第几行"。判断是否读到新文件：`FNR==1 { ... }`。

---

##### 操作符

**算术 / 赋值 / 比较 / 逻辑 / 正则全部支持：**

| 类别 | 操作符 |
|------|--------|
| 算术 | `+ - * / % ^`（`^` 幂） |
| 赋值 | `= += -= *= /= %= ^=` |
| 比较 | `== != < <= > >=` |
| 逻辑 | `&& || !` |
| 三目 | `条件 ? 值A : 值B` |
| 正则匹配 | `~`（匹配）、`!~`（不匹配） |
| 数组键判断 | `键 in 数组` |
| 其它 | `++ --`、字符串**直接相邻拼接**（如 `$1"-"$2`） |

```bash
# 正则匹配：找状态码 5xx 的行
awk '$9 ~ /^5/ {print $1, $9}' access.log

# 比较 + 逻辑：200~299 之外的
awk '$9 < 200 || $9 >= 300 {print}' access.log

# 三目：根据状态码打标记
awk '{print ($9==200 ? "OK" : "FAIL"), $1}' access.log

# 拼接：IP+路径 合成一列
awk '{print $1"-"$7}' access.log
```

---

##### 常用示例（逐步进阶）

```bash
# ① 打印每行第 1 列（IP）
awk '{print $1}' access.log

# ② 默认动作省略：打印状态码 200 的整行（$9==200 是模式）
awk '$9==200' access.log

# ③ 条件 + 多列：状态码=200 的 IP 和路径
awk '$9==200 {print $1, $7}' access.log

# ④ BEGIN 设分隔符 + 打印表头
awk 'BEGIN {FS=":"; print "用户名|Shell"} {print $1"|"$7}' /etc/passwd

# ⑤ 统计 + 关联数组：每个 IP 访问次数（END 汇总）
awk '{cnt[$1]++} END {for (ip in cnt) print ip, cnt[ip]}' access.log

# ⑥ NR：只处理第 2~4 行（NR 作模式）
awk 'NR>=2 && NR<=4 {print NR": "$0}' access.log

# ⑦ 行数、字段数
awk '{print "第"NR"行, 共"NF"个字段, 最后字段="$NF}' access.log
```

---

##### 流程控制

和 C 语言几乎一致，写在 `{}` 动作里：

```bash
# if / else
awk '{ if ($9==200) ok++; else fail++ } END {print "OK:", ok, "FAIL:", fail}' access.log

# while / for 循环
awk '{ for (i=1; i<=NF; i++) print $i }' access.log   # 逐字段打印

# next：跳过当前行，直接读下一行
awk '$1=="192.168.1.10" {next} {print $1}' access.log

# exit：立即结束
awk '$9==500 {print "找到500，退出"; exit}' access.log
```

---

##### 关联数组（awk 核心特性）

数组下标**不必是数字**，可以是任意字符串，非常适合做分组统计。

```bash
awk '{cnt[$1]++} END {for (k in cnt) print k, cnt[k]}' access.log
```

| 语法 | 含义 |
|------|------|
| `cnt[$1]++` | 以 IP 为键累加计数（首次访问自动初始化为 0） |
| `for (k in 数组)` | 遍历所有键（**顺序不保证**） |
| `k in 数组` | 判断键是否存在（配合 `if`) |
| `delete 数组[键]` | 删除某键 |

> 想按键排序输出？awk 内不便排序，**管道交给 `sort`**：
> `awk '{c[$1]++} END {for (k in c) print c[k], k}' access.log | sort -rn`

##### printf 格式化输出

`print` 简单拼接，`printf` 可精确控制格式（语法同 C 的 `printf`），适合生成对齐报表。

```bash
awk '{printf "%-15s %5d\n", $1, $9}' access.log
```

| 格式符 | 含义 | 示例 |
|--------|------|------|
| `%s` | 字符串 | `%s` |
| `%d` | 整数 | `%5d`（宽 5 右对齐） |
| `%f` | 浮点数 | `%.2f`（保留 2 位小数） |
| `%c` | 字符 | `%c` |
| `%x` / `%o` | 十六 / 八进制 | `%x` |
| `%e` | 科学计数法 | `%e` |
| `%%` | 输出一个 `%` | `%%` |

| 修饰符 | 作用 |
|--------|------|
| `-` | 左对齐（默认右对齐） |
| 数字 | 最小宽度（不足补空格） |
| `.N` | 精度（小数位或截断宽度） |

**与 print 的区别**：`printf` **不自动换行**，需手动加 `\n`；`print` 自动换行、字段间自动插 `OFS`（逗号）。

##### awk 入门小结

- 最小模型：**读一行 → 自动按 `FS` 拆字段 → 匹配"模式" → 执行"动作"**。
- 想清楚要"筛选行"（用模式）还是要"算字段"（用动作里的变量/数组）。
- 记牢三件套就够日常 80%：`$NF`（末字段）、`NR`/`FNR`（行号）、关联数组统计 + `END` 汇总。
- 复杂统计（去重 top、排序）不必硬写 awk，**awk 算完管道给 `sort`/`uniq`/`head`** 更简单。

##### 补充：awk 的"模式" → 选行，不止是取列

awk 程序结构是 `模式 { 动作 }`，有**两个正交维度**：

| 维度 | 作用 | 类比 | 写法 |
|------|------|------|------|
| **模式** | **选行** | 像 grep | `/正则/`、`$3>100`、`NR==2`、`/start/,/end/` |
| **动作** | **处理列/计算** | 像 cut | `{print $2}`、`{sum+=$3}` |

```bash
# 只有模式（像 grep，默认打印整行）
awk '/^Mem:/' /proc/meminfo

# 模式 + 动作：选行 + 取列
awk '/^Mem:/ {print $2}' /proc/meminfo
```

**一行实例逐段拆解**（`free -m | awk '/^Mem:/ {print $2}'`）：

| 片段 | 含义 |
|------|------|
| `free -m` | 输出内存信息（MB） |
| `\| awk ...` | **awk 不带文件名时从 stdin 读**，所以可以接在任何命令的管道后面 |
| `/^Mem:/` | 模式：`^`=行首锚点，匹配**以 `Mem:` 开头**的行 |
| `{print $2}` | 动作：打印该行第 2 个字段（此处 = 总内存）；字段按空白切分，`$1=Mem:` |

> 等价写法：`free -m | grep '^Mem:' | awk '{print $2}'`（grep 选行 + awk 取列）≈ awk 一条搞定。
> **建议**：只选行用 `grep`；选行 + 取列/计算用 `awk` 一条更干净。

### 正则表达式速查（日常够用）

正则 = 用**符号**描述"要找的文本模式"。`grep` / `sed` / `awk` / `vim` 通用同一套基本语法。

**元字符表：**

| 符号 | 含义 | 例子 | 能匹配 |
|------|------|------|--------|
| `^` | **行首**锚点 | `^Mem:` | 以 `Mem:` 开头的行 |
| `$` | **行尾**锚点 | `error$` | 以 `error` 结尾的行 |
| `.` | 任意**单个**字符 | `a.c` | `abc`、`a1c`（不是 `ac`） |
| `*` | 前一项重复 **0 或多次** | `ab*c` | `ac`、`abc`、`abbbc` |
| `+` | 前一项重复 **1 或多次** | `ab+c` | `abc`、`abbc`（不含 `ac`） |
| `?` | 前一项 **0 或 1 次** | `colou?r` | `color`、`colour` |
| `[...]` | 字符集（其中一个） | `[0-9]`、`[abc]` | 一个数字 / a 或 b 或 c |
| `[^...]` | 字符集**取反** | `[^0-9]` | 一个非数字字符 |
| `\|` | **或** | `cat\|dog` | `cat` 或 `dog` |
| `(...)` | 分组 | `(ab)+` | `ab`、`abab` |
| `{n,m}` | 重复 n~m 次 | `[0-9]{2,4}` | 2~4 位数字 |
| `\` | 转义（去特殊含义） | `\.` | 字面点号 `.` |

> ⚠️ `^` 在**字符组内**意思相反：`[^0-9]` = 非数字；`^[0-9]` = 行首是数字。

**日常实用例子（够用版）：**

| 需求 | 正则 | 命令示例 |
|------|------|----------|
| 注释行（`#` 开头） | `^#` | `grep '^#' file` |
| **空行** | `^$` | `grep -v '^$' file`（删空行） |
| 以数字开头的行 | `^[0-9]` | `grep '^[0-9]' file` |
| **纯数字行** | `^[0-9]+$` | `grep -E '^[0-9]+$' file` |
| 行首有空格 | `^ +` | `grep '^ +' file` |
| `error` 不区分大小写 | `[Ee]rror` | `grep '[Ee]rror' app.log` |
| **状态码 5xx** | ` 5[0-9]{2} ` | `grep -E ' 5[0-9]{2} ' access.log` |
| 以 `.log` 结尾 | `\.log$` | `find . -name '*.log'` / `grep '\.log$'` |
| IP 地址（简单版） | `^[0-9.]+` | `grep -E '^[0-9.]+' file` |
| 匹配字段等于某值 | `$1 == "Mem:"`（awk） | 比正则更精确 |
| 字段匹配正则（awk） | `$1 ~ /^Mem/` | 某字段匹配才选中 |

**基础正则（BRE）vs 扩展正则（ERE）—— 一个常见坑：**

| 特性 | BRE（`grep`、`sed` 默认） | ERE（`grep -E`、`awk`、`sed -E`） |
|------|--------------------------|-----------------------------------|
| `+ ? { } ( ) \|` | **要转义**才生效：`\+`、`\?`、`\{\}`、`\(\)`、`\|` | **直接写**：`+ ? { } ( ) \|` |
| 建议 | 能用，但符号要多个 `\` | ✅ **优先用 `grep -E` 或 awk**，写法更干净 |

```bash
grep    'ab\+c'  file      # BRE：+ 要转义
grep -E 'ab+c'   file      # ERE：+ 直接写（推荐）
grep -E ' (500|401) ' access.log    # ERE 的 | 直接写
```

**易错点小结：**

| 坑 | 说明 |
|----|------|
| 正则默认是"**包含**"匹配 | 要匹配整行必须写 `^...$`（如 `^[0-9]+$`） |
| `.` 是通配符 | 想匹配字面点号写 `\.`（如 `\.log$`） |
| BRE 里 `+ ? \|` 不生效 | 记得用 `grep -E`（ERE） |
| `*` 不单独用 | `*` 修饰前一项，`^ *` 表示"行首若干空格" |
| 引号保护正则 | 正则含 `$ ( ) \|` 时用**单引号**包住，防 shell 先解释 |

### `sort` 指令详解

**作用**：对输入行**排序**，是日志统计管道里的第一环（`awk` 提取 → `sort` 排序 → `uniq` 去重计数）。默认按**字典序**升序输出到屏幕，不改原文件。

```bash
awk '{print $1}' access.log | sort        # IP 字典序升序
```

| 选项 | 作用 | 示例 |
|------|------|------|
| `-n` | 按**数字**大小排序（非字典序） | `sort -n`（1,2,10 → 而非 1,10,2） |
| `-r` | **倒序**（降序） | `sort -rn`（从大到小，排行榜常用） |
| `-u` | 排序同时**去重**（等价 `sort | uniq`） | `sort -u file` |
| `-k 列` | 按指定字段排（配合 `-t`） | `sort -t: -k3 -n /etc/passwd`（按 UID 排） |
| `-t 分隔符` | 指定字段分隔符（默认空白） | `sort -t: -k1 /etc/passwd` |
| `-c` | 检查是否已排序 | `sort -c file` |
| `-f` | 忽略大小写 | `sort -f` |
| `-h` | 按人类可读大小排（K/M/G） | `du -h \| sort -rh`（占空间最大的目录） |

> **要点**：`sort -n` 与默认字典序差别关键——数字列必须 `-n`，否则 100 会排在 20 前面。倒序排行用 `-rn`。
> 日志统计标准管道：`awk '{print $1}' log | sort | uniq -c | sort -rn`。

### `uniq` 指令详解

**作用**：**去重（仅去除相邻的重复行）**，并常配合计数。因为只处理相邻行，**使用前必须先 `sort`**，否则相同的行不相邻就漏去重。

```bash
# 错误示范：没排序，相同值不相邻，去不掉
printf 'b\na\nb\n' | uniq            # b a b（全保留）

# 正确：先 sort 让相同项相邻
printf 'b\na\nb\n' | sort | uniq     # a b
```

| 选项 | 作用 | 示例 |
|------|------|------|
| `-c` | 每行前显示**出现次数** | `sort \| uniq -c`（`  2 192.168.1.10`） |
| `-d` | 只输出**重复**的行 | `uniq -d` |
| `-u` | 只输出**唯一**（没重复过）的行 | `uniq -u` |
| `-i` | 忽略大小写 | `uniq -ci` |
| `-w N` | 只比较前 N 个字符 | `uniq -w 3` |
| `-f N` | 跳过每行前 N 个字段再比较 | `uniq -f 1` |

```bash
# 任务 7② 完整套路：提取IP → 排序 → 去重计数 → 按次数倒序 → 取第一
awk '{print $1}' access.log | sort | uniq -c | sort -rn | head -1
#     192.168.1.10  2

# 只看哪些状态码出现过（无次数）
awk '{print $9}' access.log | sort -u
```

> **记忆**：`sort -u`（一步去重）≈ `sort | uniq`（两步），但`uniq -c` 的计数能力 `sort -u` 没有，所以"统计次数"必须用 `uniq -c`。

### `cut` 指令详解

**作用**：**按列/按字符截取**每行的一部分（轻量版"取字段"）。awk 更强但 cut 简单直观，适合固定格式文本。

| 选项 | 作用 | 示例 |
|------|------|------|
| `-d 分隔符` | 指定字段分隔符（默认 Tab） | `cut -d: -f1 /etc/passwd` |
| `-f 列` | 取第几列（可 `1,3`、`1-3`、`2-`） | `cut -d: -f1,3 /etc/passwd` |
| `-c 字符` | 按字符位置取 | `cut -c1-5 file` |
| `-b 字节` | 按字节位置取 | `cut -b1-3` |
| `--complement` | 反向（取除指定外的列） | `cut -d: --complement -f7` |

```bash
# 取 IP（第 1 列，空格分隔）
cut -d' ' -f1 access.log

# 取状态码和大小：字段 9 和 10
cut -d' ' -f9,10 access.log

# 处理 passwd：用户名 + UID
cut -d: -f1,3 /etc/passwd
```

> **cut vs awk 区别**：cut 不能加条件过滤、不能统计、多个连续分隔符难处理；awk 全能。**取固定列 → cut 足够；要过滤/统计 → awk**。
> cut 的三段式写法速记：`-d` 定分隔符、`-f` 选字段（与 `-d` 配合）、`-c` 按字符数。

```bash
# ① 先运行（后台 &）拿到 PID：用 $! 记录刚启动后台进程的 PID
```

### `ps` 指令详解（进程快照）

**作用**：列出当前进程快照（process status）。排查"进程在不在、PID 是多少、占多少 CPU/内存"。

| 选项 | 作用 | 示例 |
|------|------|------|
| `-e` / `-A` | 显示**所有**进程 | `ps -e` |
| `-f` | 完整格式（含父进程 PPID、启动命令 CMD） | `ps -ef` |
| `-a` | 显示所有带终端的进程（含他人） | `ps -a` |
| `-u 用户` | 显示某用户进程 | `ps -u drow` |
| `-p PID` | 按 PID 查单个进程 | `ps -p 12345` |
| `-o 字段` | 自定义输出列 | `ps -eo pid,ppid,stat,cmd` |
| `-L` | 查看线程 | `ps -eLf` |
| `aux` | **BSD 风格全进程**（最常用） | `ps aux` |

```bash
ps aux                          # 最常用：全部进程 + CPU/内存占比
ps aux | grep webapp            # 过滤找目标（会多出 grep 自身那行）
ps -eo pid,ppid,stat,cmd | grep webapp   # 用完整格式看 PPID 与状态 STAT
ps -fp $(pgrep -f webapp)       # 用 pgrep 找 PID 再查详情
```

> `ps aux` 输出列：`USER PID %CPU %MEM VSZ RSS TTY STAT START TIME COMMAND`。找僵尸进程就看 `STAT` 列的 **`Z`**。
> 记忆：`ps aux` 最常用；要**看父子关系/启动命令**用 `ps -ef`；要机器可读的自定义列用 `-o`。

### `curl` 指令详解（命令行访问 HTTP）

**作用**：命令行里发 HTTP 请求 / 下载文件，验证 Web 服务是否正常、看响应头状态码。

| 选项 | 作用 | 示例 |
|------|------|------|
| `-I` / `--head` | 只取**响应头** | `curl -I http://localhost:8080` |
| `-s` | 静默（去掉进度条/错误信息） | `curl -s URL` |
| `-o 文件` | 输出保存到文件 | `curl -o page.html URL` |
| `-w '格式'` | 输出额外信息（配合 `-o /dev/null`） | `curl -s -o /dev/null -w '%{http_code}' URL` |
| `-X POST` | 指定方法 | `curl -X POST URL` |
| `-d '数据'` | 提交表单/JSON 数据 | `curl -d 'name=x' URL` |
| `-H '头'` | 自定义请求头 | `curl -H 'Content-Type: application/json' URL` |
| `-L` | 跟随重定向 | `curl -L URL` |
| `-v` | 详细输出（看 TLS 握手/请求过程） | `curl -v URL` |

```bash
curl -I http://localhost:8080                     # 看 HTTP/1.1 200 OK 等响应头
curl -s -o /dev/null -w '%{http_code}\n' URL      # 只拿状态码，判断 200/502
curl -v http://localhost:8080 2>&1 | head         # 排错时看完整请求链路
```

> 常用占位符 `-w`：`%{http_code}` 状态码、`%{time_total}` 总耗时、`%{size_download}` 下载字节。排错 502/超时，`curl -v` 是最佳诊断。

### `kill` 指令详解（给进程发信号）

**作用**：给进程发**信号**（不只是"杀死"）。默认发 `SIGTERM`(15)，可指定其它信号。

| 用法 | 作用 |
|------|------|
| `kill PID` | 默认发 SIGTERM(15)，请求进程**优雅退出** |
| `kill -9 PID` | 发 SIGKILL，**强制立即杀死**（不可捕获/忽略） |
| `kill -15 PID` | 显式发 SIGTERM |
| `kill -l` | 列出所有信号名 |
| `pkill 名字` | 按**进程名**发信号（如 `pkill webapp`） |
| `killall 名字` | 按名字杀所有匹配进程 |

```bash
kill 12345                # 优雅终止（推荐先用）
sleep 2; ps -p 12345      # 确认是否已退出
kill -9 12345             # 若没死再强制杀
pkill -f webapp           # 按完整命令行匹配杀
```

> **推荐流程**：先 `kill`(15) 让程序自己清理（保存状态/关闭连接）；确实无响应再用 `kill -9`。直接 `-9` 可能丢数据、留下未清理资源。

### `nohup` 指令详解（后台持久运行）

**作用**：**no hang up**——让命令**忽略 SIGHUP 信号**（终端关闭/退出登录时触发的挂断信号），从而在后台持续运行。

| 场景 | 命令 |
|------|------|
| 后台运行且退出终端不杀 | `nohup ./webapp > /tmp/web.log 2>&1 &` |
| 重定向标准输出到日志 | `nohup cmd > out.log 2>&1 &` |
| 找到刚启动的后台 PID | 启动后紧跟 `echo $!` |
| 看服务是否起来 | `ps aux \| grep webapp` + `curl localhost:8080` |

```bash
nohup ./webapp > /tmp/web.log 2>&1 &
echo $!                    # 记录 PID（例如 23456）
```

> 语法拆解：`nohup 命令 > 日志 2>&1 &`——`>` 把 stdout 写日志；`2>&1` 把 stderr 也并入同一日志（避免"No such file"看不到报错）；`&` 放后台。**不重定向时** nohup 默认把输出写进 `nohup.out`。
> 对比：普通 `cmd &` 后台任务在**退出 shell** 时可能收到 SIGHUP 被杀；`nohup` 使其免疫，适合部署服务。

### `jobs` / `bg` / `fg` 指令详解（作业控制）

**作用**：管理**当前 shell 会话内**的后台任务（job）。注意：`nohup` 跑的是脱离 shell 的守护式进程，而 `jobs` 管的是本 shell 的前台/后台任务，两者概念不同。

| 命令 | 作用 |
|------|------|
| `jobs` | 列出当前 shell 的后台任务及其编号 `[1]`、状态 |
| `命令 &` | 直接放后台运行 |
| `Ctrl+Z` | 把**正在前台**运行的任务**挂起**（暂停，不是退出） |
| `bg %编号` | 把挂起的任务放到**后台继续运行** |
| `fg %编号` | 把后台任务调到**前台**运行 |
| `kill %编号` | 按作业编号杀任务 |

```bash
sleep 100 &                # 后台任务 1
jobs                       # 显示 [1]  running  sleep 100

./webapp                   # 前台运行，占用终端
# 按 Ctrl+Z                # 挂起 → 回到 shell 提示符
jobs                       # [2]  stopped
bg %2                      # 后台继续跑
fg %2                      # 调回前台（Ctrl+C 可终止）
```

> `%1` 指 `jobs` 里的作业编号（与 PID 不同）。新 shell（新开终端）看不到别的终端的 job——job 属于各自 shell 会话；跨会话持久运行用 `nohup`/systemd。

---

> **理论题①答案（孤儿 / 僵尸进程）：**

| 类型 | 定义 | 产生 | 查找命令 |
|------|------|------|----------|
| 孤儿进程 | 父进程已退出，子进程被 `init`（PID 1）**收养** | 父进程先死、子进程未死 | `ps -eo pid,ppid,cmd`，看 PPID 变成 1 |
| 僵尸进程 | 子进程已退出，但**父进程没调用 wait 回收**其退出状态，进程表残留 | 子进程先死、父进程未收尸 | `ps aux` 里 `STAT` 列为 `Z`；`top` 看 `zombie` 数 |

```bash
ps aux | awk '$8=="Z"'                    # 列出 STAT 为 Z 的僵尸进程
ps -eo pid,ppid,stat,cmd | grep -w Z      # 另一写法
```
> 孤儿进程通常**无害**（会被 init 接管）；僵尸进程**不占 CPU/内存**但占 PID，若大量堆积说明父进程有 bug（没回收子进程），通常需处理父进程。

> **理论题②答案（kill -9 vs -15）：**

| 信号 | 名称 | 行为 | 可被程序捕获/忽略 |
|------|------|------|-------------------|
| `kill -15` | SIGTERM | 默认终止信号，请求**优雅退出** | ✅ 可以（程序可做清理后再退出） |
| `kill -9` | SIGKILL | **强制立即杀死**，内核直接回收 | ❌ 不可以 |

> 推荐先 `kill -15`：给程序机会保存数据、释放资源、正常关闭连接。`-9` 是最后手段，直接 `-9` 可能造成数据丢失或留下不一致状态。常见流程：`kill PID` → 等 2–3 秒 → 没退再 `kill -9 PID`。

> **参考答案与命令详解**

**完整操作流程：**

```bash
# ① 看 8080 端口被哪个进程监听（ss 推荐，netstat 老命令）
```

### `ss` 指令详解（查看网络连接 / 端口监听）

**作用**：**socket statistics**，查看 socket/端口监听与连接状态。比 `netstat` 更快、信息更全，现代 Linux 首选。

| 选项 | 作用 | 示例 |
|------|------|------|
| `-t` | 只看 TCP | `ss -t` |
| `-u` | 只看 UDP | `ss -u` |
| `-l` | 只看**监听**（listen）状态的端口 | `ss -tln` |
| `-n` | 不解析名字，直接显示 IP/端口数字 | `ss -tlnp` |
| `-p` | 显示占用进程（PID/程序名） | `ss -tlnp` |
| `-a` | 显示所有连接（监听+已建立） | `ss -ta` |
| `-s` | 连接统计总览 | `ss -s` |

```bash
ss -tlnp                     # 最常用：所有 TCP 监听端口 + 对应进程
ss -tlnp | grep 8080         # 精确找 8080
ss -tn state established     # 已建立的连接
ss -s                        # 各状态连接数量总览
```

> 输出列：`Netid State Recv-Q Send-Q Local Address:Port Peer Address:Port Process`。
> **找"谁占了端口"** 就是 `ss -tlnp | grep <端口>`，看最后一列 `users:(("进程名",pid=…))`。

### `netstat` 指令详解（老牌网络查看，现多被 ss 取代）

**作用**：network statistics，老命令，功能与 `ss` 重叠。用法几乎一致，但现代系统默认可能没装（Debian 需 `net-tools` 包）。

| 选项 | 作用 |
|------|------|
| `-t` / `-u` | 只看 TCP / UDP |
| `-l` | 只看监听端口 |
| `-n` | 数字显示 IP/端口（不反解域名） |
| `-p` | 显示占用进程（需 root 才能看他人进程） |

```bash
netstat -tlnp | grep 8080    # 与 ss 等价
netstat -rn                  # 看路由表（-r 路由 -n 数字）
```

> 对比记忆：**新系统用 `ss`**，老教程/老系统常见 `netstat`；两者选项语义基本一致，会一个就会另一个。

### `nc` 指令详解（netcat，网络瑞士军刀）

**作用**：读写 TCP/UDP 连接。常用作**端口探测**、简单调试、传文件。

| 选项 | 作用 | 示例 |
|------|------|------|
| `-z` | 只扫描端口通不通，不发送数据 | `nc -z host 80` |
| `-v` | 显示详细信息（verbose） | `nc -zv host 8080` |
| `-w N` | 超时 N 秒 | `nc -zvw 3 host 80` |
| `-l` | 监听模式（当服务器） | `nc -l 9999` |
| `-u` | 用 UDP | `nc -uz host 53` |

```bash
nc -zv localhost 8080        # 测端口：succeeded! 表示通
nc -zvw 3 1.1.1.1 53         # 3 秒超时测 DNS 端口
echo test | nc localhost 9999   # 发数据测试
```

> 端口探测结果解读：`succeeded`/`open` = 通；`Connection refused` = 端口没服务；`timed out` = 被防火墙丢弃/主机不可达。

### `telnet` 指令详解（老协议客户端，兼作端口测试）

**作用**：远程登录协议（明文，不安全，现已少用），但常借它**测试某端口是否开放**——能连上说明端口通。

| 用法 | 说明 |
|------|------|
| `telnet host 端口` | 测试 TCP 端口连通性 |
| 连上后 | 进入空屏交互，按 `Ctrl+]` 进 telnet 提示符，输入 `quit` 退出 |

```bash
telnet localhost 8080
# 连上 → 黑屏/空白等待（说明端口通，可发 HTTP 请求测试）
# 失败 → Connection refused（没服务）或 timed out（被墙/不可达）
```
> 与 `nc -z` 相比，telnet 连上后会**停留交互**，适合手动发请求（如直接敲 `GET / HTTP/1.1`）验证，而 `nc -z` 只适合快速探测。

### `ping` 指令详解（测主机连通性与延迟）

**作用**：用 **ICMP** 回显请求测试目标是否可达，并显示往返延迟（RTT）。排障第一步：能不能通。

| 选项 | 作用 | 示例 |
|------|------|------|
| `-c N` | 只发 N 个包 | `ping -c 4 baidu.com` |
| `-i 秒` | 发包间隔（默认 1 秒） | `ping -i 0.5 host` |
| `-W 秒` | 超时时间 | `ping -W 2 host` |
| `-s 大小` | 包大小（默认 56 字节） | `ping -s 1000 host` |

```bash
ping -c 4 baidu.com
# 输出看：icmp_seq（包序号）、time=xx ms（往返延迟）、丢包率与统计
# 64 bytes from ...: icmp_seq=1 ttl=52 time=20.3 ms
```

> 输出末尾 `statistics`：`packet loss`（丢包率）、`min/avg/max`（延迟）。
> **注意**：ping 走 ICMP，某些主机/防火墙禁 ICMP 会 ping 不通但 HTTP 正常；反之 ping 通 ≠ 端口服务正常——所以连通性要 ping + 端口测试（nc/telnet/curl）结合。

> **理论题①答案（TCP 三次握手 / 四次挥手）：**

**三次握手（建立连接，客户端→服务端）：**
```
Client                          Server
   |---- SYN (seq=x) ----------->|   ① 客户端发起：我能连吗？
   |<--- SYN+ACK (seq=y,ack=x+1)--|   ② 服务端应答：可以，我也请你连
   |---- ACK (ack=y+1) -------->|   ③ 客户端确认：好，连接建立
```
| 步骤 | 方向 | 报文 | 含义 |
|------|------|------|------|
| ① | C→S | `SYN` | 客户端请求建立连接，携带初始序号 |
| ② | S→C | `SYN+ACK` | 服务端同意并回送自己的 SYN |
| ③ | C→S | `ACK` | 客户端确认，双方进入 ESTABLISHED |

> 为什么是三次不是两次：需要**双方都确认"自己能发、对方能收"**，两次无法让服务端确认客户端收到自己的 SYN。

**四次挥手（断开连接）：**
```
Client                          Server
   |---- FIN ---------------->|   ① 主动方：我要关了
   |<--- ACK ----------------|   ② 对方确认：收到，但我可能还有数据
   |<--- FIN ----------------|   ③ 对方：我也关
   |---- ACK ---------------->|   ④ 主动方确认，连接关闭
```
| 步骤 | 方向 | 报文 | 含义 |
|------|------|------|------|
| ① | 主动方→被动方 | `FIN` | 主动方不再发数据，申请关闭 |
| ② | 被动方→主动方 | `ACK` | 确认收到（此时半关闭，被动方仍可发数据） |
| ③ | 被动方→主动方 | `FIN` | 被动方数据发完，也申请关闭 |
| ④ | 主动方→被动方 | `ACK` | 主动方确认，彻底关闭 |

> 为什么挥手要四次而握手三次：TCP 是**全双工**，两个方向要**各自独立关闭**；被动方收到 FIN 后可能还有数据要发，所以"确认"与"自己也 FIN"分成两步。主动关闭方最后还会进入 `TIME_WAIT` 等待一段时间（2MSL），确保最后的 ACK 不丢失。

> **理论题②答案（Connection refused vs Connection timeout）：**

| 现象 | 含义 | 可能原因 |
|------|------|----------|
| `Connection refused` | 对方**明确拒绝**——收到了你的包，但目标端口没服务在监听 | 服务没启动/已崩溃、端口写错、防火墙返回 RST 拒绝 |
| `Connection timeout` | **超时**——包发出后没人应答，一直等不到结果 | 目标不可达/宕机、被防火墙**静默丢弃**（drop）、路由不通、跨网段被墙 |

> 记忆要点：
> - **refused = 端口没服务**（本机或目标机上服务没跑）→ 查 `ss -tlnp` 服务是否监听、进程是否活着。
> - **timeout = 网络层就不通**（主机不可达或被防火墙丢包）→ 先 `ping`，再逐跳 `traceroute`，检查防火墙规则（如 `iptables`/云安全组）。
> - 一个实用判断：**同一台机器上 refused vs timeout**——本地服务没起是 refused；跨公网/被防火墙 drop 通常是 timeout。

## 第七部分：Shell 脚本综合练习

### 任务 10：编写自动化备份脚本

**背景：**  
你需要每天备份 `/home/你的用户名/devops-practice/app` 目录到 `/home/你的用户名/devops-practice/backup` 下，备份文件名格式为 `app_backup_YYYYMMDD.tar.gz`，并保留最近 7 天的备份。

**要求：**  
编写一个 Shell 脚本 `backup.sh`，实现以下功能：

1. 检查备份目录是否存在，不存在则创建。  
2. 使用 `tar` 命令打包压缩 `app` 目录。  
3. 备份文件以日期命名。  
4. 删除 7 天前的旧备份。  
5. 输出日志到 `/tmp/backup.log`，格式为：`[日期时间] 备份成功/失败`。

**提示：**  
- 使用 `date +%Y%m%d` 获取日期。  
- 使用 `find ... -mtime +7 -exec rm -f {} \;` 删除旧文件。  
- 使用 `$?` 判断上一条命令是否成功。

**检查点：**  
- 脚本是否有执行权限？  
- 运行一次后，`backup` 目录下是否生成了备份文件？  
- 日志中是否有成功记录？

---

> **参考答案与命令详解**

**`backup.sh` 完整脚本：**
```bash
#!/bin/bash
# ===== 配置区 =====
APP_DIR="/home/drow/devops-practice/app"          # 要备份的目录
BACKUP_DIR="/home/drow/devops-practice/backup"    # 备份存放目录
LOG_FILE="/tmp/backup.log"                        # 日志文件
KEEP_DAYS=7                                       # 保留天数
DATE=$(date +%Y%m%d)                              # 日期，如 20250910
ARCHIVE="${BACKUP_DIR}/app_backup_${DATE}.tar.gz" # 备份文件名

# ===== 1. 确保备份目录存在（-p 已存在不报错） =====
mkdir -p "$BACKUP_DIR"

# ===== 2. 打包压缩 app 目录（-C 切到父目录，只存 app 相对路径） =====
tar -czf "$ARCHIVE" -C "$(dirname "$APP_DIR")" "$(basename "$APP_DIR")"
result=$?                                         # 捕获上条命令退出码

# ===== 3. 写日志 =====
if [ $result -eq 0 ]; then
    echo "[$(date '+%F %T')] 备份成功: $ARCHIVE" >> "$LOG_FILE"
else
    echo "[$(date '+%F %T')] 备份失败: $ARCHIVE" >> "$LOG_FILE"
    exit 1
fi

# ===== 4. 删除 7 天前的旧备份（用 +7 天；-delete 或 -exec rm） =====
find "$BACKUP_DIR" -name 'app_backup_*.tar.gz' -mtime +$KEEP_DAYS -delete
```
**使用方法：**

```bash
chmod +x backup.sh      # 赋予执行权限
./backup.sh             # 手动运行一次
ls -lh /home/drow/devops-practice/backup/   # 确认生成了 app_backup_YYYYMMDD.tar.gz
cat /tmp/backup.log     # 看日志
```

**关键点解析：**

| 要点 | 说明 |
|------|------|
| `#!/bin/bash` | shebang，指明用哪个解释器执行（不加则用当前 shell） |
| `$?` | **上一条命令的退出码**，`0` 成功、非 0 失败。必须在目标命令**紧后一行**取 |
| `$(date +%Y%m%d)` | 命令替换，把 date 输出嵌入；`$(...)` 优于旧式反引号 |
| `"$变量"` | **变量加双引号**防止路径含空格时被拆成多个参数 |
| `-C 目录` | tar 先切到该目录再打包，避免存成绝对路径（`/home/...`） |
| `-czf` | `-c` 创建、`-z` gzip 压缩、`-f` 指定文件名 |
| `-mtime +7` | 修改时间**超过 7 天**的文件（注意 `+7` 是"大于 7"，与 `-7` 相反） |

**`tar` 指令详解（打包压缩）：**

| 选项 | 作用 |
|------|------|
| `-c` | **创建**归档（create） |
| `-x` | **解包**归档（extract） |
| `-t` | 只**列出**内容不解包（list） |
| `-f 文件` | 指定归档文件名（**必须紧跟文件名**） |
| `-z` | 用 gzip 压缩/解压（`.tar.gz`） |
| `-j` | 用 bzip2（`.tar.bz2`）；`-J` 用 xz（`.tar.xz`） |
| `-v` | 显示处理过程（verbose） |
| `-C 目录` | 切换目录（打包前 / 解包到指定目录） |

```bash
tar -czf backup.tar.gz /path/to/dir     # 打包压缩
tar -tzf backup.tar.gz                  # 查看压缩包内容（不解压）
tar -xzf backup.tar.gz -C /tmp/restore  # 解压到指定目录
tar -czf app.tar.gz -C /parent app      # 只存 app/ 相对路径（推荐）
```

**脚本里那行 `-C "$(dirname "$APP_DIR")" "$(basename "$APP_DIR")"` 拆解：**

| 片段 | 含义 |
|------|------|
| `-C 目录` | 打包**前**先切换到该目录 |
| `"$(dirname "$APP_DIR")"` | `-C` 的目标 = `APP_DIR` 的**父目录** |
| `"$(basename "$APP_DIR")"` | 要打包的东西 = `APP_DIR` 的**末段名**（不含路径） |

设 `APP_DIR="/home/drow/devops-practice/app"`，则整行等价于：

```bash
tar -czf /home/drow/devops-practice/backup/app_backup_20250910.tar.gz \
    -C /home/drow/devops-practice app
# 即：切到 /home/drow/devops-practice，把其中的 app 目录打包
```

> **为什么要这么写**：若直接 `tar -czf x.tar.gz /home/drow/.../app`，归档内会存**绝对路径**（`home/drow/.../app`），解压时会还原到错误的深层目录甚至覆盖系统路径。改成"站在父目录、打包子目录名"后，归档里存的是**相对路径 `app/...`**，解压直接得到干净的 `app/` 目录，更可移植。

**`dirname` / `basename` 指令详解（路径切分）：**

| 命令 | 作用 | 示例 | 结果 |
|------|------|------|------|
| `dirname 路径` | 取**目录部分**（去掉末段） | `dirname /home/drow/app` | `/home/drow` |
| `basename 路径` | 取**末段名**（文件名/目录名） | `basename /home/drow/app` | `app` |
| `basename 路径 后缀` | 去末段并去掉指定后缀 | `basename /a/b/c.txt .txt` | `c` |

```bash
dirname /var/log/syslog         # /var/log
basename /var/log/syslog        # syslog
# 嵌在命令替换里传参（脚本常用）
tar -czf out.tar.gz -C "$(dirname "$f")" "$(basename "$f")"
```

> 两者**只做字符串切分，不访问文件系统**——路径不存在也能算出结果。常配合命令替换 `$(...)` 在脚本里动态取父目录/文件名。

**`date` 指令详解（时间格式化）：**

| 格式 | 含义 | 示例输出 |
|------|------|----------|
| `%Y` | 4 位年 | 2025 |
| `%m` | 月（01-12） | 09 |
| `%d` | 日（01-31） | 10 |
| `%H:%M:%S` | 时:分:秒 | 14:30:05 |
| `%F` | 等价 `%Y-%m-%d` | 2025-09-10 |
| `%T` | 等价 `%H:%M:%S` | 14:30:05 |
| `%s` | Unix 时间戳 | 1757... |
| `%u` | 星期（1-7） | 3 |

```bash
date +%Y%m%d              # 20250910（备份文件名常用）
date '+%F %T'             # 2025-09-10 14:30:05（日志时间戳）
date -d 'yesterday' +%F   # 昨天日期（-d 指定时间）
date -d '+7 days' +%Y%m%d # 7 天后
```

**`find ... -mtime` 清理旧文件：**

| 写法 | 含义 |
|------|------|
| `-mtime +7` | 修改时间**超过 7 天**（`+` 表示大于） |
| `-mtime -7` | **7 天以内**（`-` 表示小于） |

**Shell 脚本语法详解：**

#### 变量定义与引用

| 语法 | 作用 | 说明 |
|------|------|------|
| `var=值` | 定义/赋值变量 | ⚠️ **等号两边不能有空格**（`var = 1` 会被当成执行命令 `var`） |
| `$var` | 取值 | 最简写法，变量名后接非变量名字符时可用 |
| `${var}` | 取值（**带花括号**） | 明确变量名边界，**推荐** |
| `readonly var=值` | 只读变量 | 之后不能改 |
| `unset var` | 删除变量 | — |
| `export var=值` | 导出为**环境变量** | 子进程可见（普通变量只在当前 shell） |
| `var=$(命令)` | 把命令输出赋给变量 | 命令替换 |
| `var=$((1+2))` | 算术运算 | 整数运算 |

**`$var` 与 `${var}` 的区别（关键）：** 二者在**变量名后没有紧跟字母/数字/下划线**时**完全等价**；只有需要**划分边界**时才必须用 `${}`。

```bash
name=world
echo "$name"        # world
echo "$name123"     # ❌ 找的是变量 name123（未定义）→ 输出空
echo "${name}123"   # ✅ world123，用 {} 明确 name 的边界

	file=report
echo "${file}.tar.gz"   # report.tar.gz（. 不是变量名字符，其实 $file 也行）
echo "${file}_backup"   # report_backup（_ 是变量名字符，必须用 {}）
```

| 场景 | 用 `$var` | 用 `${var}` |
|------|-----------|-------------|
| 单独取值 | ✅ `echo $var` | ✅ 等价 |
| 后面紧跟字母/数字/下划线 | ❌ 会连读成别的变量 | ✅ `"${var}_x"` |
| 参数扩展（默认值/长度等） | ❌ 不支持 | ✅ 见下表 |
| 数组元素 | ❌ 不够清晰 | ✅ `${arr[0]}` |

**`${}` 的进阶用法（参数扩展）：**

| 写法 | 含义 |
|------|------|
| `${var}` | 取值 |
| `${var:-默认值}` | 变量**为空或未定义**时用默认值（**最常用**，防报错） |
| `${var:=默认值}` | 同上，但还会**赋值**给 var |
| `${var:+替代值}` | 变量非空时用替代值 |
| `${#var}` | 变量值的**长度** |
| `${var%.*}` / `${var##*.}` | 去后缀 / 取后缀（`%` 从右删、`#` 从左删） |

```bash
echo "${result:-100}"    # result 为空/未定义 → 输出 100（脚本防错常用）
```

#### 引号的使用（极其重要）

| 引号 | 名称 | 行为 |
|------|------|------|
| 无引号 | — | 变量会展开，结果**按空白/通配符拆分**（易出错） |
| `"双引号"` | 弱引用 | 变量、命令替换会展开，但结果**不拆分、不转义**（保原样） |
| `'单引号'` | 强引用 | **原样输出**，变量/命令替换都不展开 |
| `` `反引号` `` | 命令替换（旧式） | 等价 `$(...)`，但嵌套困难，**不推荐** |
| `$'...'` | ANSI-C 引用 | 支持 `\n`、`\t` 等转义 |

```bash
path="/home/my dir"      # 路径含空格
echo $path               # ❌ 拆成两个参数：/home/my、dir
echo "$path"             # ✅ 一个参数：/home/my dir（用双引号！）
echo '$path'             # 输出字面量 $path（单引号不展开）
```

**什么时候必须加双引号：**

| 场景 | 示例 | 不加的后果 |
|------|------|-----------|
| 变量含空格/通配符 | `rm "$file"` | 文件名带空格被拆成多个/误匹配 `*` |
| 传路径参数 | `cd "$dir"` | 路径含空格失败 |
| 命令替换结果 | `echo "$(cmd)"` | 输出被拆行、空白丢失 |
| 拼接字符串 | `"${prefix}_${name}"` | 边界不清 |

> **规则**：**除非你有意要分词或做通配符匹配，否则变量和命令替换一律套双引号**。这是 Shell 脚本最容易踩的坑。

#### 命令替换与算术

| 写法 | 作用 |
|------|------|
| `$(命令)` | 命令替换，拿输出（**推荐**，可嵌套） |
| `` `命令` `` | 同上（旧式，难嵌套，避免） |
| `$((表达式))` | 整数算术：`$((a+b))`、`$((a*2))`、`$((a%2))` |
| `$[...]` | 旧式算术（已被 `$((...))` 取代） |
| `((表达式))` | 算术运算**当条件用**：`if (( a > b ))` |

```bash
now=$(date +%F)            # 命令替换
sum=$((1 + 2 * 3))         # 算术 = 7（支持 + - * / % ** ）
((count++))                # 自增
```

#### 条件判断：`if` 的几种写法

Shell 里 `if` 后面接的是**一条命令**，用它的**退出码**判断真假（0=真，非 0=假）。下面几种"条件容器"本质都是命令：

| 写法 | 名称 | 说明 | 建议 |
|------|------|------|------|
| `if 命令; then` | 直接用命令 | 命令成功（退出码 0）即为真 | ✅ 判断命令成败 |
| `if [ 条件 ]; then` | **test** 的别名 | `[` 是个**命令**，**内侧必须有空格**，`]` 前也要空格 | POSIX 通用 |
| `if [[ 条件 ]]; then` | **bash 扩展** | 支持正则 `=~`、`&&`/`||`、字符串比较更安全 | ✅ **bash 脚本推荐** |
| `if (( 表达式 )); then` | 算术判断 | 专门做整数比较，语法像 C | ✅ 数字比较 |

```bash
# ① 直接判断命令是否成功
if grep -q "error" app.log; then echo "有错误"; fi

# ② [ ] —— 注意内侧空格！
if [ -f "$file" ]; then echo "是文件"; fi
if [ "$a" -eq "$b" ]; then echo "相等"; fi

# ③ [[ ]] —— bash 推荐，支持正则/逻辑运算符
if [[ "$name" == *.tar.gz ]]; then echo "是压缩包"; fi
if [[ "$s" =~ ^[0-9]+$ ]]; then echo "纯数字"; fi
if [[ "$a" == "x" && "$b" == "y" ]]; then echo "都满足"; fi

# ④ (( )) —— 数字比较
if (( usage > 80 )); then echo "超阈值"; fi
```

**`[ ]` vs `[[ ]]` 对比：**

| 对比项 | `[ ]`（test） | `[[ ]]`（bash 扩展） |
|--------|---------------|----------------------|
| 本质 | 外部命令（POSIX） | bash 语法关键字 |
| 空格要求 | **`[` 后、`]` 前必须有空格** | 同样需要，但更宽容 |
| 字符串比较 | `=` / `!=` 需加引号防报错 | `==` / `!=` 自动处理，**不必加引号** |
| 逻辑运算 | 需 `-a`/`-o` 或拆成两条 | 直接用 `&&` / `\|\|` |
| 正则匹配 | ❌ 不支持 | ✅ `=~` |
| 通配符匹配 | 需配合 case | ✅ `[[ $f == *.log ]]` |
| 可移植性 | ✅ 所有 shell | ❌ 仅 bash/zsh/ksh |
| 建议 | 需 sh 兼容时用 | **bash 脚本优先用 `[[ ]]`** |

> **为什么 `[` 内侧要空格**：`[` 和 `]` 是**命令名和参数**，不是语法括号。`[ -f x ]` 是命令 `[` 参数 `-f x ]`；写成 `[-f x]` 会被当成一个叫 `[-f` 的命令 → "command not found"。`[[ ]]` 是关键字，对空格更宽容，但仍建议规范写空格。

**常用判断运算符：**

| 类别 | 运算符 | 示例 |
|------|--------|------|
| 文件 | `-e` 存在、`-f` 普通文件、`-d` 目录、`-r`/`-w`/`-x` 可读/写/执行、`-s` 非空 | `[ -d "$dir" ]` |
| 字符串 | `=`/`==` 相等、`!=` 不等、`-z` 空、`-n` 非空 | `[ -z "$s" ]` |
| 整数 | `-eq -ne -gt -lt -ge -le` | `[ "$a" -gt 10 ]` |
| 逻辑 | `!` 非、`-a` 与、`-o` 或（`[[ ]]` 用 `&&`/`\|\|`） | `[ -f f -a -r f ]` |

> **整数 vs 字符串比较别混**：数字用 `-eq/-gt`，字符串用 `=`/`==`。`[ 10 > 9 ]` 是字符串比较（且 `>` 在 `[ ]` 里会被当重定向，可能生成文件！），数字比较要用 `-gt` 或 `[[ 10 -gt 9 ]]` / `(( 10 > 9 ))`。

#### `date` 里 `+` 的作用（为什么有时加有时不加）

`date` 的 `+` **不是算术加号**，而是告诉 date：**"后面跟的是输出格式串"**（format）。

| 写法 | 结果 | 说明 |
|------|------|------|
| `date` | `2025年 09月 10日 星期三 14:30:05 CST` | 不加 `+` → 用**默认格式** |
| `date +%Y%m%d` | `20250910` | 加 `+` → **自定义格式** |
| `date -d 'yesterday'` | 默认格式的昨天 | 不加 `+` → 还是默认格式 |
| `date -d 'yesterday' +%F` | `2025-09-09` | `-d` 指定时间 + `+` 指定格式 |
| `date -u` | UTC 时间的默认格式 | `-u` 是选项，非格式 |

> **规则**：**只要你想要自定义格式，就必须以 `+格式` 结尾**；只要默认输出，就不加。`-d`/`-u`/`-r` 这些**选项**与 `+` 无关、可共存。
> 记忆：`+` = "接下来是格式"，`-` = "选项"（如 `-d` 指定时间、`-u` UTC）。
> ⚠️ 格式串里有空格/特殊字符时要引号：`date '+%F %T'`。

#### 退出状态与常用语句

| 语法 | 作用 |
|------|------|
| `$?` | **上一条命令**的退出码（`0`=成功，非 0=失败） |
| `exit 0` / `exit 1` | 脚本退出并返回状态码 |
| `set -e` | 任何命令失败立即退出（严格模式，慎用） |
| `set -u` | 引用未定义变量时报错 |
| `command1 && command2` | 前一条成功才执行后一条（与） |
| `command1 \|\| command2` | 前一条失败才执行后一条（或） |
| `command &` | 后台运行 |
| `while 条件; do ...; done` | 循环 |
| `for i in 1 2 3; do ...; done` | 遍历循环 |
| `case $x in a) ...;; esac` | 分支匹配 |

```bash
# && / || 简写判断（脚本常用）
mkdir -p "$dir" && echo "创建成功" || echo "创建失败"

# 循环示例
for f in *.log; do
    echo "处理 $f"
done
```

> **易错点**：
> - `[ $result -eq 0 ]` 里变量若为空会报 "integer expression expected"，稳妥写 `[ "${result:-1}" -eq 0 ]`。
> - **定义变量等号两侧不能有空格**；`[` 内侧、`]` 前必须有空格。
> - `$?` 必须在**目标命令紧后一行**取，中间插了别的命令就拿不到原退出码。

### 任务 11：编写系统资源监控脚本

**背景：**  
你需要编写一个监控脚本，每 5 分钟检查一次系统内存使用率，如果超过 80%，则记录一条警告日志到 `/tmp/monitor.log`，并发送一封邮件（可以模拟，用 `echo` 输出即可）。

**要求：**  
1. 使用 `free` 命令获取内存使用率。  
2. 计算使用率：`used / total * 100`。  
3. 如果使用率超过阈值，输出告警信息并追加到日志。  
4. 使用 `crontab -e` 设置定时任务，每 5 分钟执行一次该脚本。

**理论问题：**  
- 解释 `crontab` 中 `*/5 * * * *` 的含义。  
- 如何查看当前用户的定时任务？如何删除所有定时任务？

---

> **参考答案与命令详解**

**`monitor.sh` 完整脚本：**
```bash
#!/bin/bash
# ===== 配置区 =====
THRESHOLD=80                                # 告警阈值（百分比）
LOG_FILE="/tmp/monitor.log"                 # 告警日志

# ===== 1. 用 free 取内存数据（取 Mem: 那一行，$2=total $3=used，单位 MB） =====
total=$(free -m | awk '/^Mem:/ {print $2}')
used=$(free -m  | awk '/^Mem:/ {print $3}')

# ===== 2. 计算使用率 =====
# 用 awk 做浮点计算（bc 也可）；先乘 100 再除避免整数截断为 0
usage=$(awk -v u="$used" -v t="$total" 'BEGIN {printf "%.1f", u/t*100}')

# ===== 3. 超阈值则告警 + 记录日志（邮件用 echo 模拟） =====
if awk -v x="$usage" -v y="$THRESHOLD" 'BEGIN {exit !(x > y)}'; then
    msg="[$(date '+%F %T')] 警告: 内存使用率 ${usage}% 超过阈值 ${THRESHOLD}% (used=${used}MB/total=${total}MB)"
    echo "$msg" >> "$LOG_FILE"
    echo "邮件模拟: $msg"        # 真实环境可换成 mail -s "内存告警" root@localhost
else
    echo "[$(date '+%F %T')] 正常: 内存使用率 ${usage}%"
fi
```
**使用方法：**
```bash
chmod +x monitor.sh
./monitor.sh                        # 手动跑一次测试
crontab -e                          # 编辑当前用户定时任务，加入下面一行：
# */5 * * * * /home/drow/devops-practice/scripts/monitor.sh >> /tmp/monitor_cron.log 2>&1
```

**计算使用率的几种写法：**

| 方式 | 写法 | 说明 |
|------|------|------|
| awk（推荐） | `awk -v u=$used -v t=$total 'BEGIN{printf "%.1f", u/t*100}'` | 支持浮点，无需额外工具 |
| bc | `echo "scale=1; $used*100/$total" \| bc` | 需装 bc；注意 `scale` 控制小数位 |
| Shell 整数 | `$(( used * 100 / total ))` | **只能整数**，小于 100% 会截断成 0，不推荐 |
| 直接取 | `free | awk '/Mem:/ {printf "%.0f", $3/$2*100}'` | 一条命令搞定（$3=used $2=total） |

**`free` 输出字段（回顾）：**

| 列 | 含义 |
|----|------|
| total | 物理内存总量 |
| used | 已用（含部分缓存，判断压力建议看 available） |
| free | 完全空闲 |
| buff/cache | 内核缓冲/缓存（可回收） |
| available | **真正可用**（新程序能拿到的量） |

> 更贴近真实的监控应算 **`(total - available) / total * 100`**，因为 `buff/cache` 可回收，只看 `used` 会偏高。

**`crontab` 指令详解（定时任务）：**

**cron 表达式 5 个字段：** `分 时 日 月 周 命令`

```
*  *  *  *  *  command
│  │  │  │  └─ 星期 (0-7，0和7都是周日)
│  │  │  └──── 月 (1-12)
│  │  └─────── 日 (1-31)
│  └────────── 时 (0-23)
└───────────── 分 (0-59)
```

| 符号 | 含义 | 示例 |
|------|------|------|
| `*` | 任意值（每个） | `* * * * *` 每分钟 |
| `*/N` | **每 N 个单位** | `*/5 * * * *` 每 5 分钟 |
| `a-b` | 范围 | `0 9-18 * * *` 9 点到 18 点每小时 |
| `a,b,c` | 枚举 | `0 0 * * 1,3,5` 周一三五零点 |
| `a-b/c` | 范围内每 c | `0 */2 * * *` 每 2 小时 |

```bash
*/5 * * * *  /path/monitor.sh           # 每 5 分钟执行一次
0 3 * * *    /path/backup.sh            # 每天凌晨 3 点备份
30 8 * * 1-5 /path/task.sh              # 工作日 8:30
```

| 命令 | 作用 |
|------|------|
| `crontab -e` | 编辑当前用户的定时任务（首次会选编辑器） |
| `crontab -l` | **列出**当前用户的定时任务 |
| `crontab -r` | **删除**当前用户的**所有**定时任务（⚠️ 无确认，慎用） |
| `crontab -u 用户 -l` | root 查看指定用户的定时任务 |
| `crontab 文件名` | 用文件内容覆盖定时任务 |

```bash
crontab -l                  # 查看
crontab -e                  # 编辑
crontab -r                  # 清空所有（删除全部）
```
> **注意**：cron 任务的环境变量很"干净"（PATH 短、无你 shell 的配置），所以**命令建议写绝对路径**、脚本里 `#!/bin/bash` 要写全，输出重定向到日志方便排错。

> **理论题①答案（`*/5 * * * *`）：** 5 个字段依次为「分 时 日 月 周」。`*/5` 表示**分钟位每 5 分钟**触发一次（即 0、5、10、15…55 分），其余字段 `*` 表示不限。所以含义是**每 5 分钟执行一次该命令**，等价于每个小时执行 12 次。

> **理论题②答案：**
> - **查看**当前用户定时任务：`crontab -l`
> - **删除全部**定时任务：`crontab -r`（删除当前用户所有任务，无提示，务必谨慎）
> - 若要编辑（删除部分），用 `crontab -e` 手动改；root 操作用户：`crontab -u 用户名 -l/-r`

### 任务 12：模拟故障排查

**场景：**  
你的 Web 服务突然无法访问，返回 502 错误。请写出你的排查步骤，至少包含以下命令的使用：

- `ps` / `top`
